# Государственная религия: эффект и политическое окно

`set_religion_from_primary_culture = yes` — явный эффект области страны. Он
читает текущую основную культуру, обходит POP во всех принадлежащих стране
провинциях и суммирует численность этой культуры по религиям. Признанные
культуры и принадлежность провинции контролёру не влияют на выбор.

При равенстве максимумов сохраняется текущая государственная религия, если
она среди лидеров. Иначе выбирается первая религия в стабильном порядке
определений движка. При отсутствии подходящего населения изменение не
выполняется, в логе появляется `NO_POPULATION`. Повтор с уже выбранной
религией возвращает `UNCHANGED` без дублирования записи истории страны.

Эффект регистрируется `religion.patch` в существующем dispatcher
`CCore_AssimilateBlock.cpp`. Для разбора скалярного `yes` используется
штатная фабрика bool-effect с временным неактивным токеном; исходный токен
восстанавливается через `__finally`. Только после установки собственной
таблицы методов включается payload. При отказе регистрации в дереве
остаётся неактивный carrier, который не ассимилирует POP. Таблица методов
заменяет исполнение и подсказку только нового эффекта. Обычный `assimilate`
не меняется. Исполнение происходит синхронно на потоке вызывающего скрипта;
фонового наблюдения за основной культурой и периодического обхода POP нет.

Расчёт в `calculation.cpp` отделён от чтения памяти и мутации. `native.cpp`
проверяет диапазоны массивов, идентичность страны и владельцев, циклы POP,
указатели профессий и соответствие религий реестру. Смена религии выполняет
настоящий `CReligionEffect::Execute`, включая штатную запись истории.
Неверная область, неизвестный EXE/ABI и повреждённые данные диагностируются;
неудача не выдаётся за успешное применение.

Область страны содержит канонический пустой `CPop` в `scope+0x14`; этот
указатель сравнивается с `*(gameBase+0xE58A10)`, а не только с null. Реальные
POP и провинциальные области отклоняются. Отказ исполнения включает в лог
восемь начальных DWORD контекста и адрес пустого POP для диагностики ABI.
Подсказка сохраняет владение переданным по значению GameString: освобождает
его heap-buffer через штатный `CoreFreeGameString` в `__finally`, включая
отказ локализации. В копии CAssimilateEffect сохранены все 14 методов.

`ccore_state_religion_ui.dll` — отдельный модуль интерфейса. Он использует
готовые религию страны и атлас из 14 значков, не читает POP. Перехваты
полного обновления и кадрового обслуживания политического окна сохраняют
исходные возвраты EAX. Указатели на страны и GUI не сохраняются между
вызовами. Подпись обновляется только при изменении; неизвестная религия
скрывает значок и показывает «Не указана». Имена религий берутся из
`localisation/country_state_religion.csv`, без изменения общих POP-ключей.

`revanchism` и `revanchism_value` сохранены за пределами экрана: штатный
updater разыменовывает результат поиска `revanchism_value` без проверки
null. Размер окна не меняется. `government_desc` остаётся описанием
правительства, поэтому окончательная приёмка его переноса требует GUI.

| Контракт Victoria II 3.04 x86 | Адрес / поле |
|---|---|
| Государственная религия страны | `country+0xE68` |
| Основная культура | `country+0xE64` |
| Принадлежащие стране провинции: массив ID | `country+0x9D8..0x9DC` |
| POP: size / culture / religion / next | `+0x58 / +0x6C / +0x70 / +0x27C` |
| Менеджер религий, RVA указателя | `0xE5EA24` |
| Реестр религий, индекс 0 служебный | `manager+0x1C..0x20` |
| Религия: индекс / ключ / локализованное имя / кадр | `+8 / +0x10 / +0x2C / +0x70` |
| Штатная смена религии, VA | `00894520`, thiscall, два stack-аргумента, `ret 8` |
| Politics vtable, RVA | `0xA0E458`, slots 11 и 6 |

| Lookup icon / instantTextBox | GUI root vtable `+0x44 / +0x3C` |
| Значок: показать / скрыть / кадр | vtable `+0x34 / +0x38 / +0x48` |
| Текст: GameString / renderer | widget `+0xDC / +0xA0` |
| Renderer текста, VA | `00A5ECC0`, ESI=renderer, два stack-аргумента, `ret 8` |

Адреса рассчитаны относительно предпочитаемой базы EXE `00400000`; код
использует фактический `gameBase` и RVA. Допускается только EXE с SHA-256
`62d48c204364dd706584777c2e2b3c7ab3c5f1dd0170872554943575d53d6648`.
Проверка сигнатур не заменяет семантическую квалификацию настоящим движком.

Проверки без игры:

```powershell
python tools/creatinecore/religion/build_native.py
python -m unittest discover -s tools/creatinecore -p test_install.py
python tools/creatinecore/validate_native_sites.py
```

Изолированная сборка находится в `.work/culture-religion-native`. Первый
C++ тест проверяет выбор, веса, фильтрацию, ничьи, отсутствие населения и
переполнение. Второй вызывает настоящий native reader на синтетическом
образе памяти: две провинции, несколько культур, неверная область,
несогласованный владелец, цикл POP и повреждённый реестр. Третий линкует
настоящий `effect.cpp` с тестовым окружением и вводит ошибки фабрики:
неверный класс, недоступный tail, отсутствие нового узла, исключение после
создания узла и недоступную vtable. Проверяются неактивность carrier и
восстановление токена во всех отказах. Тесты не запускают Victoria II.
Дополнительно проверяются непустой dummy POP области страны, отклонение
настоящего POP, освобождение длинного аргумента подсказки при успешной
локализации, fallback, исключении и null-output, а также SSO.
`build.py` собирает core и UI вместе и фиксирует их исходники,
оба патча, GUI и CSV в общем манифесте. `install.py` проверяет весь пакет до
записи и сохраняет существующие настройки пользователя.

Обязательная движковая приёмка: решение после `MakePrimary`, большинство
за пределами столицы, чужая культура, обе разновидности ничьей, отсутствие
POP, повтор и сохранение/загрузка; идентичный результат у двух участников
MP. GUI требует настоящего изображения всех 14 значков, длинных русских
названий и правительства, смены страны/религии при открытом окне, загрузки
другой кампании, проверки соседних подсказок и отсутствия реваншизма.
Эти испытания выполняет главный агент; одна компиляция их не подтверждает.
