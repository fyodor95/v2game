# Сборка CreatineCore для этой сборки Victoria II

Исходная версия: [7d9f9df9b356096cde475ebd550fbb0102fa1042](https://github.com/artyom-kuznetsov/V2DLL_Victoria-2-Extension/tree/7d9f9df9b356096cde475ebd550fbb0102fa1042), CreatineCore 6.43.

Команда из корня репозитория:

```powershell
python tools/creatinecore/build.py
python tools/creatinecore/test_config_alias.py
python tools/creatinecore/validate_native_sites.py
```

Нужны Git, Python 3.12 и Visual Studio 2026 с MSVC v145, Windows SDK и поддержкой x86. Первый запуск получает закреплённые файлы из GitHub. В среде Codex сборка MSBuild может требовать штатного разрешённого запуска вне песочницы: её FileTracker иначе завершается ошибкой доступа. Скрипт не повышает права самостоятельно.

Исходники и промежуточные результаты находятся в `.work/creatinecore`; этот каталог не предназначен для коммита. Результат в `build/` — `creatinecore.dll`, `dinput8.dll`, `eventmusic.dll`, `ccore_script_fixes.dll`, `ccore_great_power_culture_cores.dll`, `great_power_culture_cores.ini`, `events/great_power_culture_cores.txt`, `localisation/great_power_culture_cores.csv` и общий `manifest.json` с SHA-256 и размерами. Событие `3997200` и его русская локализация копируются из текущих игровых данных репозитория; staging сохраняет их байты CP1251 и CRLF. GPC собирается последовательно после ядра; его манифест дополнительно фиксирует хеши всех собственных заголовков и исходников. Сам скрипт не устанавливает файлы в игру и не запускает её. Это отдельная операция интеграции после проверки.

`python tools/creatinecore/install.py --destination <копия-игры>` проверяет EXE,
наличие, SHA-256 и размер всех обязательных артефактов, включая событие и CSV.
Старый пакет без этих ресурсов или записей о них в манифесте отклоняется до
записи в игру. Установщик читает ресурсы из `build/`, создаёт полную резервную
копию заменяемых файлов и прежнего манифеста в `.work/install-backups` до
первой записи в destination, затем устанавливает сборку. Предыдущие версии
события и CSV заменяются проверенными байтами пакета. Существующие INI ядра
и GPC сохраняются побайтно, включая неизвестные опции. При частичном сбое
резервная копия и `result.json` остаются для восстановления; автоматическое
удаление резервов не выполняется. Новый GPC INI по умолчанию выключен;
существующий профиль сохраняется. В текущей основной сборке механика включена.
Проверки установщика и объединения артефактов:
`python -m unittest discover -s tools/creatinecore -p test_install.py`.

Локальный `v2game.patch` исправляет чтение `BUILDING_GOODS_CONSUMPTION`, сохраняя старый alias. Документированный ключ имеет приоритет внутри одного файла независимо от порядка строк; противоречие диагностируется. Каждый следующий файл конфигурации начинает собственный учёт ключей. Патч также заменяет подписи условий флага провинции локализуемыми префиксами и экспортирует адаптер того же локализатора для дополнительного плагина. Обнаруженный при запуске безусловный сканер памяти фабрик переведён под явно читаемую настройку `PATCH_FACTORY_DUMP_SCAN`, выключенную по умолчанию; одного `DEBUG_LOG=0` для его отключения в исходной версии было недостаточно.

`extract_script_fixes.py` выделяет из закреплённого `Source/v2dll_country_daily_optimizer/v2dll_mod.cpp` только реализацию `date`, своевременного включения календарных событий в кандидаты и защиту подсказок неизвестных модификаторов. Используются соответствующие вспомогательные функции и x86-переходники upstream. Код настройки AI, пропуска стран, изменения периодичности сканирования, правил марионеток и мультиплеера в генерируемую DLL не включается.

Плагин требует ключи `CC_DATE_AT_LEAST`, `CC_DATE_BEFORE`, `CC_INVALID_MODIFIER`. Ядро требует `CC_PROVINCE_FLAG_IS`, `CC_PROVINCE_FLAG_IS_NOT`. Префиксы не содержат подстановок: имя флага или дата дописываются кодом. Отдельный плагин устанавливается после встроенных патчей ядра через `dll_Submods`. Статическая проверка сигнатур подтверждает соответствие исходному EXE, но не заменяет проверку установки hooks и поведения в запущенной игре.

Тест alias компилирует именно извлечённые ветви реального C++-парсера и проверяет обе формы, выключение, оба порядка конфликтующих строк, совпадающие значения, регистр и сброс между слоями. Проверка EXE сверяет 23 исходные точки изменения.

Диагностика боевой линии исправлена: upstream забывал передать счётчик `stayOk` в строку с `%d/3`, поэтому отображаемое число могло быть мусором со стека. Алгоритм патча при этом не меняется. Регистрация `CREATE_SUBSTATE` и установка `NEW_POP_MODIFIERS` теперь выводят фактический результат соответствующего установщика. Для `COMBAT_SECOND_LINE_DAMAGE_REDIRECT` upstream безусловно возвращает отказ: автор установил, что старая точка перехвата не была функцией применения урона. Локальная сборка не снимает эту защиту; настройка отложена пользователем.

Новый `religion.patch` добавляет явный country-effect `set_religion_from_primary_culture = yes` в существующий dispatcher. Пакет также содержит `ccore_state_religion_ui.dll`, `interface/country_politics.gui` и `localisation/country_state_religion.csv`; установщик проверяет и сохраняет резервные копии этих ресурсов наравне с остальными. Манифест фиксирует оба патча и исходники модуля религии. Контракты, отдельные тесты и ограничения движковой приёмки описаны в [документации модуля](religion/README.md). `validate_native_sites.py` теперь проверяет 23 точки, включая штатную смену религии и политический интерфейс.

Первоначальные исходники сохраняют своё авторство и уведомления upstream. Используемый ядром MinHook сопровождается копией `notices/MinHook-LICENSE.txt`; дополнительные уведомления берутся из закреплённого дерева исходников. Это не лицензия на игровые файлы Victoria II.
