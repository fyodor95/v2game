# Кандидат нативного сохранения Victoria II 3.04

Исследован локальный EXE с SHA-256 `62d48c204364dd706584777c2e2b3c7ab3c5f1dd0170872554943575d53d6648`. Это статическая реконструкция, а не подтверждение безопасного выполнения.

Функция VA `0x00675A80`, RVA `0x275A80`:

- Начальные байты: `55 8B EC 6A FF 68 AC E3 B9 00 64 A1`.
- `ECX` указывает на игровую строку пути внутри виртуальной файловой системы, например `save games/checkpoint.v2`.
- Первый аргумент стека — живой `CInGameIdler*`.
- Завершение обычного пути — `ret 4` по адресу `0x00675BD4`.
- Предполагаемая сигнатура адаптера: `void (__thiscall*)(EngineString* path, void* idler)`.

Два независимых статических вызова подтверждают раскладку: `0x006759EF` и `0x006761B6`. Перед вторым выполняются `mov edx,[ebp-18h]; push edx; lea ecx,[ebp-0DCh]; call 00675A80`. Вызывающая функция `0x00675870` начинает путь с литерала `save games/` по адресу `0x00E092FC`. Для активного мода она может строить префикс мода с `/save games/` (`0x00E09308`), затем дописывает имя файла. Это не абсолютный путь ОС.

Тело создаёт файловый объект через `0x00992740`, передавая путь и режим записи; затем формирует сериализующий поток. Файловый конструктор вызывает `0x00B21F00`, а тот — `0x00B21D30`: код нормализует виртуальное имя через `0x00B1FB50` и открывает его относительно глобального каталога записи (`0x00F20A84`). Поэтому абсолютный путь Windows не является допустимым аргументом этого файлового маршрута. На `0x00675B70` берётся глобальный мир из `0x012588E8`, а на `0x00675B85` вызывается его виртуальная функция `vtable+4` с указателем потока. Следующий блок закрывает файловый объект. Имеются взаимодействия с индикатором сохранения через `idler+0x17E8`, а завершающий вызов `0x0066EEE0` управляет игровым меню.

Не передавать современный `std::string`: использовать существующий адаптер старого игрового строкового ABI и игровой аллокатор. Вызывать на проверенном потоке владельца, только после загрузки кампании. Передавать виртуальное имя `save games/<basename>.v2`; полный путь ОС использовать только для проверки существования и результата. До вызова необходимо подтвердить, что `userdir.txt` направляет каталог записи именно в отдельный тестовый пользовательский каталог. Возврат функции не считать доказательством успешного сохранения: нужны наличие/завершение записи файла, корректный заголовок и загрузка результата новым процессом.

## Исправление первоначальной интерпретации

Первоначальная версия этой заметки ошибочно описывала аргумент как полный путь Windows. При проверке такого вызова основной агент получил `E_SAVE_MISSING`; затем соответствующий процесс игры завершился. Причина завершения отдельно не установлена, и её нельзя автоматически приписывать файловому пути. После этого исследование обоих вызывающих участков и файлового конструктора выявило описанный выше контракт виртуального относительного имени. Успешное сохранение и загрузка результата должны подтверждаться отдельным runtime-прогоном; статические инструкции этого не доказывают.

Каталог Smedley подтверждает загрузку и выход, но не содержит проверенного контракта сохранения; его bounded runs сами сейв не записывают. Нативная консольная команда `save` для этой игры также не установлена. Поэтому этот кандидат требует собственного runtime-подтверждения DLL-мостом.
