# Профиль и русификация CreatineCore

Профиль рассчитан на коммит `7d9f9df9b356096cde475ebd550fbb0102fa1042`
CreatineCore 6.43 и исходники, полученные скриптом сборки в
`.work/creatinecore/upstream`. Это подготовленные настройки, а не подтверждение
установки перехватов: их успешное подключение проверяется игровыми логами.

После получения исходников выполнить:

```powershell
python tools/creatinecore-profile/prepare.py --write
python tools/creatinecore-profile/prepare.py
python -m unittest discover -s tools/creatinecore-profile -p "test_*.py"
```

Без `--write` скрипт только проверяет файлы. Он не устанавливает DLL и не
запускает игру. `creatinecore_settings.ini` предназначен для копирования в
`z_CreatineCore` при установке проверенного комплекта. Рабочий профиль не
переключается на неизвестный конфиг мода (`LOCAL_MOD_CONFIG=0`).

Профиль включает запрошенные расширения и исправления существующих команд.
Перенаправление урона второй линии (`COMBAT_SECOND_LINE_DAMAGE_REDIRECT`)
отложено по решению пользователя: профиль явно задаёт `0`. Приоритет размещения
поддерживающих частей во второй линии остаётся включённым.
Незапрошенные изменения боёв, поведения AI, колониальной промышленности,
сетевой симуляции и дополнительные DLL-оптимизаторы выключены. Параллельное
сканирование событий/решений и квантование POP не используются. Исправления
скриптов из отдельного плагина подключаются на стадии его сборки и проверки.

Цены экспоненциальные; процентный алгоритм и расширение потолка выключены.
`MAX_FACTORY_MONEY_SAVE=3000` задаёт резерв на уровень фабрики и откладывает
выплату излишка владельцам. Это ориентир по GFM, не универсальная защита от
переполнений. В `defines_ccore.txt` явно задана нулевая глобальная прибавка
доходов; возможности `pop_income_modifier` остаются доступны скриптам.

Содержание зданий пока не вводится в обычную кампанию: `goods_consumption` не
добавлен в определения зданий. Поддержка механизма, строка бюджета и переводы
подготовлены для изолированных сценариев и будущих согласованных ставок.

Игровые CSV и defines записываются в Windows-1251, инструменты и документация —
в UTF-8. Две существующие строки дохода POP изменяются по их ключам в
`all_orig.csv`; дублирующие переводы не создаются. Значения и подстановки всех
строк штатного `creatinecore.csv` проверяются автоматически.

Визуальное размещение строки бюджета необходимо проверить в игре. Этот
инструмент не утверждает, что её читабельность или механики уже прошли игровой
тест.
