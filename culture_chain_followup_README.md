# Короткий полуавтоматический прогон FOLLOWUP v1

## Запуск

1. Полностью перезапустить игру без мода после установки новых файлов.
2. Начать новую одноразовую партию 1 января 1836 года за любую страну, поставить паузу.
3. Ввести в консоли:

   ```text
   tag HAW
   event 3999500
   ```

4. Нажать OK, закрыть консоль и запустить время. Оставаться за Гавайи, другие тесты не запускать.
5. Примерно через 24 игровых дня появится `SAVE AS chain_auto_followup`.
   Нажать OK, поставить паузу, сохранить отдельным именем **chain_auto_followup** и сообщить агенту «готово».
6. Если до 5 февраля окна нет, всё равно сохранить с этим именем и сообщить об отсутствии окна.

Первый файл `chain_auto_result` не перезаписывать: он содержит полезные результаты.
Подготовка опять меняет население, владельцев, культуры и корки — только новая тестовая партия.
Для остановки новых служебных этапов: `event 3999512`; уже вызванные помощники могут завершиться.

## Что изменилось и что проверяется

Первый прогон завершил все 17 этапов без зарегистрированных войн, но не подтвердил
подготовку населения. Новый набор возвращает два свойства ранее успешного ручного
теста: подготовка происходит у PRU, а передача и ассимиляция находятся в отдельных
блоках провинции. Это восстановление известного образца, а не доказательство причины
сбоя старого способа.

День 4: отдельно фиксируются культуры 301–303, владельцы через owner/tag,
результат owned_by=ENG и культуры стран. Нет одного общего флага, скрывающего причину ошибки.

День 6: провинциальный источник 301 под ENG вызывает три независимых помощника PRU:

- литеральные проверки FROM, owner/tag=PRU, owned_by=PRU и старое owned_by=THIS;
- отдельный кандидат `FROM = { owner = { tag = THIS } }`;
- прежний совмещённый защитный фильтр, выдающий корку.

День 10: фиксируется наличие PRU-корки и фактический владелец 301.
День 12: 303 передаётся PRU, её PRU-корка удаляется; через два дня аналогичные
три помощника проверяют собственную провинцию. День 17: снимок владельца и корки 303.
День 24: финальное уведомление. Наблюдатель проверяет войны раз в игровой день.

Проверяемые культурные и ownership-условия записаны в `manifest.json` — это ожидания.
Новые конструкции изолированы: отсутствие помощника не считается отрицательным
результатом его условия. В зависимости от фактических результатов возможен ещё
один более узкий тест; этот прогон не обещает доказать всю производственную механику.

## Установка и анализ

19 новых событий по одному на файл `D:\v2game\events\zz_chain_followup_*.txt`.
Старые файлы не меняются. Загрузку проверять по setup.log: #1 на каждый файл.
Анализатор и статическая проверка находятся в репозитории:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\autogen\experiments\culture_chain_followup\analyze.ps1 -SavePath "D:\Documents\Paradox Interactive\Victoria II\save games\chain_auto_followup.v2"
powershell -NoProfile -ExecutionPolicy Bypass -File D:\autogen\experiments\culture_chain_followup\validate.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File D:\autogen\experiments\culture_chain_followup\test-analyzer.ps1
```

Можно добавить `-AsJson` к анализатору. MATCH/MISMATCH — сравнение отдельного флага
с ожиданием, не заключение об общей корректности. NOT_EXECUTED означает отсутствие
контрольной отметки выполнения. Перед интерпретацией проверить отсутствие войны,
выполнение подготовки и источников. Финальное сохранение дополнительно позволяет
прочитать настоящий состав POP и владельцев. Игра запускается пользователем;
синтетические проверки анализатора не подменяют запуск движка.
