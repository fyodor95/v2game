# MECHANISMS v2 — полуавтоматическое исследование скриптов Victoria II

Статус: подготовленный эксперимент, **не подтверждение работы механизмов**.
Отдельный набор, не заменяющий прежние стенды и сохранения.

## Что сделать в игре

1. Полностью закрыть и заново запустить Victoria II после установки файлов. В лаунчере не выбирать мод.
2. Начать **новую одноразовую партию 1 января 1836 года**, поставить паузу.
3. Ввести в консоли:

   ```text
   tag HAW
   event 3997000
   ```

4. Подтвердить старт, закрыть консоль, запустить время. Оставаться за Гавайи; не запускать старые тесты, не менять тег и не применять другие консольные команды.
5. Будет одно промежуточное окно **PLAYER CHECK — click OK normally**. Просто нажать OK и продолжить время. Держать окно открытым специально не нужно.
6. Примерно через **132 игровых дня** появится **SAVE AS culture_mechanisms_auto**. Нажать OK, поставить паузу и сохранить отдельным именем **culture_mechanisms_auto**. Сообщить агенту «готово».
7. Если к **1 июня 1836 года** финального окна нет, всё равно сохранить под этим именем и сообщить, какое окно было последним. Неполный прогон тоже полезен.

Не перезаписывать `chain_auto_result` и `chain_auto_followup`. Для аварийной остановки: `event 3997001`. Стоп прекращает новые диагностические эффекты, но не отменяет уже появившиеся окна и не откатывает сохранение. Для повторения нужна новая партия.

## Что меняется

Только в тестовой партии меняются основная и признанные культуры PRU, основные культуры ENG/USA, диагностические PRU/FRA-корки провинции 301 и служебные флаги. **Владельцы и POP не меняются**, команд `secede_province` и `assimilate` нет. Настройки войн, агрессивности ИИ и исходные файлы населения не изменяются. Ежедневный наблюдатель отмечает войну любой из PRU/ENG/USA/FRA/SWI/HAW; такой прогон нельзя считать чистым. Короткие изменения между снимками могут быть пропущены.

## Проверки

256 событий по одному на файл; 395 наблюдений, включая буквальные контроли. Количество диагностических файлов **не является предлагаемой архитектурой мода**. Стенд исследует отдельные механизмы, не измеряет стоимость промышленного алгоритма.

### A. Девять культурных фаз, дни 1–89

Каждая фаза: изменение культур стран → независимый снимок через два дня → изолированные кандидаты → повторный снимок. Имеющиеся корки не используются как культурный критерий.

| Фаза | Провинция | Основная PRU | Признанные PRU из тестового набора | Основная владельца |
|---|---|---|---|---|
| A1 | 301, british | british | south_german | french |
| A2 | 301 | north_german | british | french |
| A3 | 301 | north_german | south_german | french |
| A4 | 301 | french | south_german | french |
| A5 | 301 | north_german | french | french |
| A6 | 301 | north_german | french | british |
| A7 | 149, смешанная | yankee | south_german | french |
| A8 | 149 | north_german | dixie, afro_american | french |
| A9 | 149 | north_german | yankee | french |

У провинции 149 по исходным POP крупнейшая культура — yankee, но менее 50%; dixie и afro_american вместе превышают 50%. Анализатор дополнительно читает реальные POP итогового сохранения. Это не снимок населения в каждый день теста, поэтому пограничный/изменившийся состав требует осторожной интерпретации.

В каждой фазе отдельно проверяются:

- страновые `is_primary_culture` / `is_accepted_culture` с `THIS` при корневой провинции;
- страновые `primary_culture` / `accepted_culture` с `THIS` — отдельные гипотезы, поддержка не предполагается;
- те же четыре варианта с `FROM` у PRU после вызова из провинциального события;
- `FROM = { culture = THIS }` у PRU;
- страновые булевы варианты `yes`/`no`, чтобы обнаружить возможную булеву интерпретацию аргумента;
- литеральные культурные контроли; для смешанной провинции — отдельные проверки крупнейшей культуры и доли yankee 40%/50% (последние сами являются проверяемым синтаксисом).

Гипотеза правильного динамического сравнения: primary положительно в A1/A7, primary-or-accepted — A1/A2/A7/A9. A4/A5 специально отделяют культуру населения от основной культуры владельца. A8 отделяет крупнейшую культуру от суммы признанных. Для `accepted_culture` основная культура не считается автоматически включённой в гипотезу; буквальные контроли позволяют увидеть реальное поведение.

### B. Метки и собственное владение, дни 91–116

Метка `csm2_claimant` сначала у PRU, затем у FRA, затем снова у PRU после удаления её диагностической корки 301. Изолированно проверяются `any_core = { has_country_flag = ... }`, метка владельца и буквальные контроли.

Положительный пример собственного владения — **уже прусская 549**, без передачи чужой провинции. Провинциальные источники 301 и 549 вызывают помощников PRU с проверками `owned_by = THIS`, `owner = { tag = THIS }`, `is_core = THIS`, `any_core = { tag = THIS }` внутри `FROM`. Наличие собственной корки 549 не мешает отдельной проверке владения.

### C. Вызовы и immediate, дни 118–132

Из настоящего события вызываются отдельные события с истинным и невозможным `trigger`, с задержкой 0 и 2 дня. Учитываются и `immediate`, и `option`; консоль не используется для вызова этих кандидатов. Отсутствие выполнения не считается подавлением условиями без подтверждения загрузки файла и положительного контрольного вызова.

Для ИИ и человека отдельно записывается, исполнился ли `immediate` до возврата вызывающего события и до `option`. Одно человеческое промежуточное окно нужно именно для этой проверки. Стенд не предполагает синхронность вложенных событий.

## Установка и проверка

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\autogen\experiments\culture_mechanisms_auto\validate.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File D:\autogen\experiments\culture_mechanisms_auto\test-analyzer.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File D:\autogen\experiments\culture_mechanisms_auto\test-generated.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File D:\autogen\experiments\culture_mechanisms_auto\install.ps1 -GamePath D:\v2game
```

Установка добавляет только `events\zz_culture_mechanisms_*.txt` и эту инструкцию под именем `culture_mechanisms_auto_README.md`. При отличающемся уже существующем файле останавливается, не перезаписывает его. Установщик проверяет ID и хеши. Старые эксперименты не меняются; их периодические флаги отключаются в тестовом сохранении при старте.

Если игра перестанет загружаться из-за проверяемого синтаксиса, сохранить логи и временно переместить **только** новые `zz_culture_mechanisms_*.txt` из `events` в отдельную папку вне `events`. Не удалять оригинальные игровые файлы. Отдельные неподдержанные кандидаты затем можно исключить, сохранив остальные проверки.

Генератор `generate.ps1` возвращает JSON «имя файла → содержимое» в stdout, ничего не записывает. `-Offset` / `-Count` позволяют получить части набора. Сгенерированные файлы и manifest хранятся рядом; изменение генератора требует их согласованного обновления.

## Анализ

До нового запуска игры сохранить её `setup.log`: он нужен для проверки загрузки событий. Обычно агент прочитает сохранение и лог сам после сообщения «готово».

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\autogen\experiments\culture_mechanisms_auto\analyze.ps1 -SavePath "D:\Documents\Paradox Interactive\Victoria II\save games\culture_mechanisms_auto.v2" -AsJson
```

Путь к `setup.log` можно передать через `-SetupLogPath`. Нужно #1 для каждого из 256 файлов. Пустой `error.log` этого не заменяет. Исходные файлы и установленные можно сверить через `validate.ps1 -CheckInstalled`.

Статусы: MATCH/MISMATCH — сравнение измерения с гипотезой; OBSERVED — наблюдение без заранее предполагаемого ответа; NOT_EXECUTED/INCOMPLETE — не хватает выполнения; INVALID_SETUP — окружение/война/слишком позднее измерение; HARNESS_ERROR — отсутствуют обе ветки результата либо отмечены обе; NOT_LOADED/UNVERIFIED_LOAD — нет достоверной загрузки; CANCELLED/NOT_STARTED — прогон остановлен или не запускался. Сырые результаты сохраняются и при недостоверном окружении.

Этот прогон не подтверждает естественный MTTH 60 месяцев, технологический барьер, равенство полной производственной схемы для ИИ/человека, производительность или готовую архитектуру. Полученные закономерности записываются в AGENTS.md **после** анализа реального прогона, не заранее.
