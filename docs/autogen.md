# Генератор autogen

`autogen/` — сабмодуль репозитория `git@github.com:fyodor95/autogen.git` с C++-генератором игровых данных, событий, решений и локализации Victoria II. При подключении закреплён коммит `c9191371be6c7279d411fa695d1a49bdf7abea70` — локальный `master` в `D:/autogen`. Он получен независимым локальным клонированием; исходная рабочая копия сохранена. Этот коммит на момент подключения на два коммита опережал локальный `origin/master`; наличие его на сервере не проверялось, публикация не выполнялась.

Решение Visual Studio — `autogen/autogen.sln`, точка запуска — `autogen/run_program/run.cpp`. Генератор подготавливает данные, формирует игровые скрипты и проверяет идентификаторы событий и решений. Остальные каталоги `autogen*` в сборке сохраняют прежние генераторы.

Программа читает свой `autogen.cfg` по пути `../autogen.cfg` относительно рабочего каталога процесса; в нём задаётся `game_path`. Затем она читает игровой файл `<game_path>/autogen.cfg` с параметрами генерации и необязательным `mod_subpath`. Эти два файла имеют разное назначение. Игровой `autogen.cfg` в корне сборки сохранён; локальная конфигурация программы не переносится из `D:/autogen`.

Запуск генератора изменяет игровые данные. Его сборка, настройка и запуск выполняются отдельной задачей с проверкой выходных файлов; подключение сабмодуля само по себе генерацию не запускает.

После получения основного репозитория сабмодуль восстанавливается командой `git submodule update --init -- autogen`. Она использует закреплённый коммит; запись `branch = master` в `.gitmodules` относится к явному обновлению через `--remote`. Правила обновления указателей и сохранности отдельной рабочей копии находятся в `AGENTS/docs/git.md`.
