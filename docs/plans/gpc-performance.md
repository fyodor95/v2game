# Измерение стоимости обычных дней GPC

Это оставшаяся проверка производительности из
[общего плана](great-power-culture-cores.md). Скрипт
[`benchmark_gpc.py`](../../tools/vic2test/benchmark_gpc.py) подготавливает настоящий
сравнительный прогон. Наличие скрипта не означает, что измерения уже проведены.
Результаты и вывод о пороге 5% появляются только из реальных выборок.

## Стадия 1. Предусловия и исходный материал

Использовать одну существующую изолированную SP-среду с `environment.json` внутри
`.work`. EXE должен совпадать с квалифицированным 3.04; `userdir.txt` должен вести
в собственный `userdata`, автосохранения отключены, режим оконный. Игры других
задач бенчмарк не ищет и не завершает. Главный агент обеспечивает отсутствие
параллельного игрового/ресурсоёмкого прогона на время измерения.

Стартовый материал — копия `gpc31_empty.v2`. Для подготовленного материала
известны 193 активных служебных флага, `pass=2`, `seed=1282378555`. Скрипт не
доверяет только имени файла: читает настоящий `date/flags`, проверяет dual-rail
кодек/checksum, завершённую сохранённую дату и прогнозирует каждый тик на весь
интервал **один день прогрева плюс измеряемые дни**. При любом ожидаемом полном
проходе запуск запрещён; файл не исправляется и RNG не подбирается. При другом
значении `--days` прогноз проверяется заново.

Настройки: MTTH 60, `ENABLE_RNG_PROBE=0`; переменная `VIC2_GPC_TEST_ALWAYS`
должна отсутствовать, probe/mutation-переменные и квалификационные DLL запрещены.
`BUILDING_GOODS_CONSUMPTION=0` проверяется в тестовой и основной конфигурациях.
Основная конфигурация только читается. Меняется единственное числовое значение
`ENABLE_GREAT_POWER_CULTURE_CORES` тестового INI; остальные байты сохраняются.

До первого запуска зафиксировать SHA-256 EXE/DLL/INI, исходной копии сейва,
настроек baseline и инструментов. Полный fingerprint переиспользует MP preflight:
он включает игровые данные, скрипты, карту, ресурсы и неизвестные каталоги.
Бенчмарк дополнительно включает исключённые из MP-сравнения `game/userdir.txt`,
`settings.txt` и `messagetypes_custom.txt`, а также оба файла настроек из
`userdata`. Учитывается и отсутствие необязательного override. Исключаются
только журналы и производные `map/cache`, `gfx/cache`, как в MP helper.

Штатное отключение звука тестовой среды через `cli.mute_test_settings` выполняется
до фиксации baseline, чтобы fingerprint описывал действительные параметры
запуска. Перед каждым режимом и после завершения входы сверяются с baseline;
разрешено только ожидаемое изменение числового GPC-переключателя. Самостоятельные
изменения скриптов или настроек делают сравнение недействительным. Отчёт и каталог
артефактов создаются только под новыми именами. Существующий отчёт нельзя
переиспользовать, даже неполный.

## Стадия 2. Жизненный цикл и границы измерения

Для каждого режима `off`, затем `on`:

1. Установить режим в тестовом INI и вызвать `cli.start(hidden=True, save=...)`.
   Сохранить новую session и получить `OwnedProcess` с удерживаемым handle.
   Не вызывать `V2Mod_Init`, debug `run`, консольные изменения мира или GUI.
2. Выполнить один день `advance --auto-events` вне измерения. Для включённой
   механики CLI дожидается завершения дневной фазы GPC. Проверить паузу, SP,
   исходную дату плюс день, native pass/RNG/checksum против Python-прогноза.
3. Измерить `time.perf_counter` вокруг одной CLI-команды
   `advance --days 100 --auto-events`. По умолчанию дополнительно снять
   `GetProcessTimes` на том же удерживаемом handle до/после команды.
4. Проверить фактическую длительность через разность `date_raw / 24`, целевую
   дату, сохранность номера прохода и точное ожидаемое расписание. Сохранить
   полный ответ команды и число выбранных первых опций событий отдельно для
   прогрева и измерения. Полный проход GPC делает этот замер непригодным.
5. Перед следующей выборкой вызвать `cli.return_to_menu`, затем
   `cli.load_campaign` исходного сейва в том же процессе. Повторить прогрев.
   Проверить неизменность PID/token и одинаковое состояние начала выборки.
6. После трёх выборок завершить только собственный процесс через его handle,
   скопировать точные байты журналов в новый каталог артефактов и перейти к
   другому режиму с новым процессом.

Сопоставимость начала проверяется по дате, открытым event windows, счётчику
auto-events и полному публичному GPC status. Общие поля сверяются и между off/on.
Это проверка доступного наблюдаемого состояния, а не доказательство побитового
равенства всех мировых объектов. Source save SHA должен оставаться неизменным.

Загрузка/возврат/прогрев и чтение контрольного status находятся вне таймера.
Запуск маленького Python CLI-процесса, IPC и опрос завершения входят в wall time
одинаково в обоих режимах. CPU учитывает только игровой процесс; это полезная
вторая метрика, а не замена пользовательского wall time.

Выключенный runtime может ответить после изменения даты, но до окончания
обработки дня. Это относится и к прогреву, и к концу измеряемого интервала.
Включённый дожидается GPC-барьера. Поэтому off потенциально включает остаток
прогревочного дня и исключает остаток последнего; стоимость этих остатков может
различаться. Знак погрешности отношения on/off неизвестен: его нельзя считать
гарантированной верхней оценкой расходов или автоматически исправить на 1%.
В отчёте явно указывается эта неопределённость; численная поправка не применяется.

Квалификация штатного `return_to_menu/load_campaign` выполняется главным агентом
до запуска этого бенчмарка. При отказе перехода автоматического повтора команды
или подмены процесса нет: сохраняется ошибка и завершается созданная сессия.

## Стадия 3. Оценка и отчёт

Для каждой выборки вычислить `wall_seconds / actual_days`, затем медиану отдельно
для `off` и `on`. Формула сравнения:

```text
overhead_percent = (median_on / median_off - 1) * 100
```

Порог — `<= 5%`. В отчёте должны быть все шесть реальных длительностей, медианы,
фактические дни, CPU (если включён), native состояния, число автоматических
выборов, конфигурации, хеши и журналы. При превышении порога `complete=true`,
но `ok=false`: измерение состоялось, критерий не пройден. При неполном прогоне
`complete=false`, медианы не выдаются за окончательный результат.

Три выборки — минимальная проверка, не строгая статистическая оценка устойчивого
эффекта. При пограничном/шумном результате повторить полный прогон новым отчётом
с `--order on-off`, убедившись в сопоставимой внешней нагрузке. Не выбрасывать
неудобные выборки и не запускать дополнительные проверки ради улучшения цифры.
Сначала установить причину: фоновые события, разброс CPU/стенда, несовпадение
старта, журналирование, обычное чтение/запись 193 флагов. Новое изменение кода
повторно открывает затронутую проверку.

Этот сценарий не измеряет сам полный проход: обход POP, расчёт, штатную выдачу и
уведомления. Их измерение остаётся отдельным пунктом общего плана; замеры между
проходами не дают права объявить его выполненным.

## Сохранность и отказ

Session публикуется целым JSON через собственный временный файл и `os.replace`;
ошибка до replace оставляет прежний session неизменным. Пока публикация не
завершена, `cli.start` отвечает за cleanup созданного `Popen` по удерживаемому
handle, включая ошибку записи и прерывание. При ошибке загрузки после публикации
бенчмарк проверяет смену token и получает `OwnedProcess` именно новой сессии.
Чужая или неизменившаяся session не является разрешением завершать процесс.
Если cleanup не подтверждён, сообщить ошибку, не искать процессы по имени и не
повторять мутацию. На каждый режим сохраняются native log и полный session.

В `finally` восстановить точные исходные байты тестового INI, проверить SHA
неизменяемых игровых входов, настроек и исходного сейва, дописать отчёт об ошибке. Отчёт
перезаписывается только после собственного эксклюзивного создания в этом запуске.
Если сам каталог вывода недопустим, файл уже существует либо файловая система не
позволяет запись, ошибка печатается без перезаписи чужого файла.

Пример для уже подготовленной и свободной среды:

```powershell
python -B tools/vic2test/benchmark_gpc.py --environment .work/gpc-probe2 --output .work/gpc-benchmark-ordinary-01.json
```

`--days` допускает 1–365, `--samples` — 3–9; по умолчанию 100 и 3.
`--timeout` ограничивает каждый advance, `--transition-timeout` — повторные
переходы. Первый `cli.start(save=...)` использует собственный срок загрузки CLI
600 секунд. `--no-cpu` отключает дополнительную метрику CPU. Другой исходный сейв
задаётся только именем его существующей копии в этом userdata через `--save`.

## Проверка инструмента до игрового запуска

Выполнены AST-проверка Python и шесть изолированных pure/mock-проверок без игры:
побайтное сохранение CP1251/CRLF INI; odd/even RNG; обнаружение производственного
срабатывания; чтение готового/повреждённого кодека; cleanup новой session после
ошибки загрузки; отсутствие cleanup неизменившейся чужой session. Тесты cleanup
использовали подставной `OwnedProcess` и временные файлы, а не настоящие PID.

Дополнительно read-only прочитана существующая копия `gpc31_empty.v2`:
`1931.1.2`, `date_raw=60715584`, `last_day=704816`, `seed=rng=1282378555`,
`pass_sequence=2`, checksum `2296293863`, 193 активных флага. Прогноз 101 дня
содержит 51 draw, ни одного due; конечные `last_day=704917`, `rng=3728492837`,
checksum `789557587`, pass остаётся 2. Это проверка исходных условий,
**не измерение производительности и не результат игрового прогона**.

После исправлений ревью 16 ноября 2026 года прошли 35 проверок: 10 в
[`test_start_session.py`](../../tools/vic2test/test_start_session.py), 7 в
[`test_benchmark_gpc.py`](../../tools/vic2test/test_benchmark_gpc.py), 8 существующих
тестов CLI и 10 тестов архивации журналов. Проверены частичная запись JSON,
отказ replace, прерывание, cleanup только созданного процесса, сохранность
прежней session, изменения скриптов/карты/настроек и запрет запуска при
несовпадении входов. Процессы в этих проверках подставные; настоящая игра
не запускалась. Порог 5% и матрица игровых замеров не изменены.

```powershell
python -B -m unittest discover -s tools/vic2test -p test_start_session.py
python -B -m unittest discover -s tools/vic2test -p test_benchmark_gpc.py
python -B -m unittest discover -s tools/vic2test -p test_cli.py
```
