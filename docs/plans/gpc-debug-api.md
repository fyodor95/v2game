# Ограниченный debug API механики GPC

## Результат и границы

Завершить обещанные `culture-cores preview`, `snapshot`, `run` через C ABI
производственного модуля. Bridge/CLI подключает главный агент отдельно.
API доступен только в изолированном стенде с `VIC2_TEST_SESSION`. Это тот же
признак, который уже использует тестовая инфраструктура; новый alias не вводится.

Preview и snapshot читают полный согласованный снимок и вычисляют пары без
изменения симуляции. Они не вызывают seed/RNG, не записывают флаги, не продвигают
дату и допустимы в MP после подтверждённого общего барьера. Run допустим только
в SP и выполняет один явно помеченный принудительный проход без нового RNG.
Периодический производственный планировщик и его вероятность не меняются.

## Стадии

1. Зафиксировать C ABI в `debug_api.h`: версии и размеры, enum операции,
   ограниченное ASCII-имя нового JSON, числовой результат/ошибка и inline path.
   Не передавать указатели движка, STL и владение выделенной памятью.
2. В `runtime_debug.h` реализовать защитные read-only predicates, JSON для
   стран/провинций/всех крупнейших культур/имеющихся корок/тегов/пар и создание
   нового файла через `CREATE_NEW` внутри собственного `userdata/gpc-debug`.
3. Выделить существующий цикл Preflight → writing → ApplyCore → Notify → digest
   в общий `ApplyPass`, сохранив порядок производственного пути. Подключить
   exported dispatcher в runtime без изменения TickSchedule/seed.
4. Главный агент подключает CLI и квалифицирует новый API в изолированной игре.
   До этого экспорт считается реализованным, но не runtime-проверенным.

## Инварианты и отказ

На входе требуются owner thread, равный подтверждённому simulationThread,
`failed=0`, `busy=0`, `enabled=1`, `has_schedule=1`, пауза и отсутствие исполняемой
игровой команды. Обе даты кэша обязаны совпадать с сырой датой мира. При run
проверяются оба MP-признака: byte `idler+0x5C` и byte `world+0xBB8`; ненулевой
признак запрещает операцию до чтения/записи расписания и до полной выборки мира.
Второе поле подтверждено нативными записями `0064BD21..0064BD30`.

Файл резервируется под новым именем до первой мутации. Никакие существующие
файлы, включая неполный результат предыдущей команды, не перезаписываются.
Run декодирует сохранённое расписание, сверяет его с фазой/кэшем, увеличивает
только pass_sequence; rng, seed и last_day остаются прежними. Preflight охватывает
все пары и уведомления до записи маркера. После попытки native мутации ошибка
оставляет writing marker/неопределённый исход и устанавливает sticky failed.
Автоматический повтор запрещён. Успешная фиксация публикуется в status cache.

JSON содержит входной снимок и рассчитанные пары. Для run отдельно отмечается
успех фиксации. Если запись JSON не завершилась после уже успешной фиксации,
результат явно сообщает committed=1 и ошибку вывода; повторять run нельзя.
Полный снимок POP и указатели движка для воспроизведения Calculate не нужны:
его входом служат доминирующие культуры после квалифицированного суммирования.

## Проверки при интеграции

- Preview/snapshot при общей паузе не меняют дату, schedule checksum/RNG,
  множества корок и число уведомлений; JSON читается независимым oracle.
- Повтор имени отвергается без native writes; неверные enum/размер/version,
  поток, дата, busy/failed и отсутствие стенда дают явную ошибку.
- MP run отвергается по каждому из двух признаков отдельно, без RNG/флагов.
- SP run выдаёт точно preview-пары, увеличивает pass на единицу, сохраняет
  rng/seed/last_day; повтор preview пуст, уведомлений нет при нулевой выдаче.
- Ошибка Preflight происходит до writing; ошибка после начала мутаций не
  публикует успешный статус и требует завершения процесса.
- Сохранение и загрузка после run подтверждают новые корки и schedule checksum.
