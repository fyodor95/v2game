## Стадия 1: квалификация нативных контрактов

Порядок: статическое исследование → адаптеры с проверками сигнатур → маленький
изолированный runtime-сценарий → сохранение и повторная загрузка → ревью.
Не устанавливать экспериментальные перехваты в основную игру.

Два независимых исследователя изучают mutator/GP/технологии и планировщик/MTTH.
Они не изменяют Git, игровые данные, сборочные каталоги и внешнее состояние.
Главный агент интегрирует результаты и отвечает за единственный тестовый стенд.

Необходимые инварианты: операции только в подтверждённой фазе симуляции;
нет указателей между кампаниями; настоящий mutator обновляет обе стороны корок;
состояние расписания находится внутри `.v2`; UI не влияет на общий результат.

Завершение стадии: доказательства ABI и поведения всех необходимых операций,
включая точную вероятность/период проверки MTTH и сетевую передачу состояния.
Статическое исследование само по себе этот критерий не выполняет.

## Независимая подготовка вычислительного модуля

Расчёт кандидатов можно разрабатывать без нативных мутаций. Вход — снимок стран,
провинций и POP; выход — отсортированные пары идентификаторов. Это не означает
завершения стадии 1 и не разрешает установку функции до runtime-квалификации.
Тестировать на явных ожидаемых множествах и независимой медленной реализации.
Ничья крупнейших культур передаётся адаптером после квалификации правила движка.

## Интеграционный прототип

Для нативного модуля выбрана отдельная DLL через имеющийся `V2ModAPI`:
новой фабрики скриптовых эффектов нет, достаточно единственного проверенного
call-site дневного сканирования. Это сохраняет воспроизводимую сборку ядра
без дополнительного изменения его большого translation unit. Настройки модуля
находятся в отдельном `z_CreatineCore/great_power_culture_cores.ini`; основной
профиль пользователя не заменяется. Экспериментальная и производственная DLL
не устанавливаются одновременно на один call-site.

Прототип собирается отдельно и испытывается только в `.work`. До сетевой
квалификации он не устанавливается в основную игру. Перед его испытаниями
проверить reader, полный итератор флагов, операции и уведомления; после мутаций
сохранять writing до проверки итогового состояния. Нативная ошибка оставляет
маркер незавершённой операции и запрещает автоматическое повторение.

## Результаты промежуточной проверки

Уточнение пользователя: при равенстве численности крупнейших культур выдавать
корки для **всех** культур, разделивших первое место. Объединять получателей:
одна пара «провинция — держава» добавляется один раз, даже если подходит несколько
культур ничьей. Это небольшое расширение уже существующего расчёта сумм POP;
случайный выбор культуры не используется. Штатный выбор одной культуры остаётся
только контрольным наблюдением при квалификации агрегатов.

Последующее уточнение пользователя имеет приоритет: **только основная культура
державы**, без признанных. Индекс получателей строится только по primary.
При ничьей каждая из крупнейших культур может дать корку державе с такой основной
культурой. Accepted не участвуют ни в отборе, ни в объединении населения.
Потеря прежней основной культуры не отзывает ранее выданные корки; сохранение
её среди признанных не даёт новых корок. Исходный полный план выше не переписывается:
это уточнение заменяет соответствующие условия плана и тестовой матрицы.

- Чистый расчёт: MSVC Win32, 4023 проверки, включая 2000 случайных миров и
  перестановки входных данных; результат совпадает с независимым перебором.
- Чистый планировщик/кодек: MSVC Win32 `/W4 /WX`, 32148 проверок.
- Python oracle сохранений: 9 проверок; настоящий сейв 1891 года разобран без
  редактирования исходника. Подготовка стенда и обработка срока: 8 проверок.
- На копии 1891 года post-events callback выполнен ровно один раз на каждый из
  пяти дней: даты 60365184…60365280, шаг 24, поток симуляции совпал с мостом.
- Настоящие объекты тестовых событий: MTTH60=1800000/555,
  MTTH1month=30000/33333, MTTH1day=1000/1000000. Все три runtime-проверки прошли.
- Native lookup nationalism: индекс 82; прочитаны восемь настоящих GP.
  У CHI уровень 0, у остальных семи — 1, что важно для фильтра получателей.
- На провинцию 658 выдана одна корка ENG. Forward=1, reverse=1, dirty=1.
  Повтор — без вызова mutator. В сохранении список изменился с HAW/USA на
  HAW/USA/ENG; новый процесс увидел существующую корку без повторной выдачи.
- Запись состояния через native global flags и обратное чтение прошли:
  seed=876226818; RNG 1380999279 на нечётном дне 690225, неизменен на чётном
  690226, затем 2515027809 на 690227. В образе 193 активных служебных флага.
- Хеш исходного пользовательского 1891.v2 остался
  `a3030d8b26101ee7e040bcf138a0bc53b8ab1a6e1e0ce322da3d6e73eceab0e5`.

Это частичная квалификация стадии 1: сетевой контракт, крупнейшая культура,
перенос состояния через загрузку и остальные критерии ещё проверяются.
Основная игра не изменена. Квалификационный DLL находится только в `.work`.

Первая загрузка стенда выявила слишком короткий 15-секундный срок отдельного
первого запроса. Две сессии были завершены после IPC timeout без повторного
выполнения неоднозначной команды. Исправлен срок запроса в пределах общего
дедлайна; следующий запуск автоматически загрузил кампанию.

## Интеграционные результаты: основные культуры

Текущие правила проверены повторно: 4030 нативных проверок расчёта,
32148 планировщика, 11 Python-проверок независимого oracle.
Reader обработал 289 стран, 3248 провинций и 37454 POP. Предпросмотр с
квалификацией агрегатов дал 24 пары за 500 мс; независимый oracle дал те же пары.

Полный модуль: первый проход добавил 24 корки за 485 мс; последующие два — 0.
Выданы три уведомления: AUS, NGF, SIC. Независимая разность сохранений содержит
ровно ожидаемые 24 пары, без удалений и лишних пар; оставшихся кандидатов 0.
Исходный и итоговый SHA находятся в `docs/research/gpc-validation.json`.
После загрузки результат продолжил работать: 50 дополнительных ускоренных
проходов, все пустые, без ошибок. Обычные фоновые события тестовой копии
обработаны явным `--auto-events` (3 первых опции).

Полный итератор глобальных флагов прочитал 193 активных флага; обновления
изменяли 44/58 флагов в проверенных двух дневных фазах. Seed не переинициализировался.
Состояние триггера writing очищалось только после обратной проверки.

Русское уведомление открыто в настоящем GUI и закрыто кнопкой «Принято».
Корка существовала до кнопки. Снимок сделан до уточнения primary-only;
текст локализации затем исправлен, новый текст включён в изолированный модуль.
Попытка сохранить открытое окно не выполнилась из-за имени длиннее 15 символов;
проверка сохранения именно с неподтверждённым окном остаётся открытой.

Ревью обнаружило две исправленные проблемы: запись transaction marker до
проверки сигнатур setter/clearer; несовместимость seed entry со штатной
диагностикой RNG. Добавлены предварительная проверка и распознавание только
конкретного перехвата CreatineCore с проверкой trampoline/модуля/возврата.
Квалификация RNG с включённой диагностикой ещё требуется.

После нативной ошибки модуль останавливается до перезапуска процесса, как
отравленный CLI-мост. Другая кампания в том же повреждённом процессе не является
способом восстановления. Нормальные загрузки читают состояние из текущего мира;
снимки и указатели между callback не сохраняются.

Сетевые среды: `.work/gpc-mp-host` и `.work/gpc-mp-client`.
Основная игра по-прежнему не содержит новой DLL. Чужой изменённый `autogen`
оставлен вне изменений и коммитов задачи.
