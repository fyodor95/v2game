# Нативные сетевые испытания без ввода в GUI

Уточнение пользователя: повторные сетевые проверки выполнять без управления
мышью/клавиатурой; работающий драйвер закоммитить и описать в канонических
руководствах CLI и проверок AGENTS.

## Контракт

Использовать настоящие callbacks лобби и очередь сетевых команд движка.
Окна могут оставаться скрытыми; отсутствие рендера не подменяет запуск двух
реальных участников. Обычные SP-команды `pause`, `advance`, `event` и `save`
в сетевой сессии по умолчанию запрещены.

Действия CLI `mp`: открытие меню, host/join, выбор сохранения и страны,
frontend Play, Start ожидания, штатная сетевая пауза и поэтапная смена скорости.
Выбор кнопки события использует штатный CSelectEventOptionCommand.
Изменение возвращает queued; завершение подтверждается отдельным опросом
обоих участников. Не повторять отправленную команду при неизвестном исходе.

Контроллер Python должен проверять изоляцию и совпадение данных/конфигураций,
создавать двух участников, выполнять сценарий, сравнивать даты/состояния/
контрольные суммы, сохранять отчёт и завершать только свои процессы.
Начальный GUI-прогон — контроль исходной сборки, не приёмка нового модуля.

## Стадии

1. Статически квалифицировать UI callbacks и сетевые очереди; отдельно от
   локальных Execute-команд. Документы: `docs/research/gpc-mp-*-contracts.md`.
2. Собрать адаптеры, подтвердить скрытые host/join, загрузку и выбор стран.
3. Подтвердить Play/Start и паузу/скорость на обоих участниках; проверить отказ
   локальных SP-команд и отказ клиента на управление хостовой скоростью.
4. Подтвердить сетевую обработку собственного уведомления и безопасное
   сохранение хостом при общей паузе. Ошибки не дают фиктивного успеха.
5. Автоматизировать сценарий; выполнить одинаковые контрольные конфигурации
   без модуля, с выключенным и включённым модулем. Проверить перехост.
6. После реальной квалификации описать команды, готовность, диагностику и
   ограничения в `tools/vic2test/README.md`; устойчивое правило — в AGENTS.

## Промежуточные доказательства

Два скрытых процесса запущены. Первое открытие MP уже выполнило native Signal,
но поиск результата использовал неверные поля и вернул E_NOT_READY.
Runtime RTTI подтвердил CFrontEnd; readonly-проверка выявила правильный массив
экранов по primary root+0x74C/+0x750, восемь прямых указателей на view.
Индекс 3 содержит SP view, индекс 4 — MP view; owner обоих равен primary root.
Это исправляется в адаптере перед следующей сборкой. Нельзя заменять этот
результат неподтверждённым предположением о root+4 или root+0x34.

## Подтверждённое управление

Исправленный адаптер выполнил без физического ввода host/join, загрузку сейва
1891, выбор AUS/NGF и Play на двух участниках. Первый Start получил отказ
до enqueue: peer ещё был в списке ожидания. После готовности штатный Start
выполнился; добавлен read-only `can_start` для ожидания перед отправкой.

Скорости `0→4` и снятие паузы подтверждены обоими участниками. Первоначальный
guard `executing` отклонял паузу до enqueue; независимое исследование доказало,
что для upper pause/speed он избыточен: producer публикует команду, не вызывает
её Execute. Этот guard удалён только для двух операций очереди.

Повторный 20-дневный прогон завершился общей паузой на raw date `60370296`,
без pending у обоих. В журналах контрольной партии 214 дневных SYNC-записей
на участника, все пары sum совпали, `first_real=-`. Пять отрицательных проверок
подтвердили запрет клиентского управления скоростью и SP-мутаций в MP.
Артефакты: `.work/gpc-artifacts/native-controls-02.json`, `native-negative-01.json`,
`native-baseline-{host,client}-oos.log`.

Повтор полной последовательности `mp_driver.py --start --days 20` прошёл
на новом мосте: raw date `60365160→60365640`, 20 одинаковых дневных SYNC.
`--save-result mp_native_01` создал 41001899 байт, SHA-256
`9a84383151924df83448769ad82ccc36c470b4ea1e63da44c2f28d506835a5c3`.
Сохранение разобрано независимым parser (3963 корневых entries), повторная
запись и сохранение клиентом отвергнуты. Чтение native списка событий работает
у обоих (пока пустой список); выбор настоящей опции ещё проверяется.

Preflight сравнивает все входные файлы с узкими исключениями; первый полный
запуск подтвердил равенство 9577 файлов. Последующий отказ выявил особенность
Windows: одно iterdir меняет directory st_size `0→28672` без записи. Для каталогов
вместо размера проверяются inode/type/mtime и точный список детей; файловые
проверки размера и SHA сохранены. Регрессии: 14 passed, 1 skipped (symlink privilege),
настоящий junction отвергается.

Перехост `native-rehost-03.json` прошёл со сменой ролей: новый host NGF,
client AUS, загрузка `mp_native_01.v2`, ещё 4 дня до raw date `60365736`,
повторное сохранение `mp_rehost_01.v2` (41271431 байт). Обе копии загрузили
новую DLL с enabled=0; read-only C ABI вернул одинаковый пустой кэш без
обработки расписания. Фазовый контроль и сравнение текущих PID-журналов дали
полные совпадающие GPC-disabled и native SYNC доказательства:
`.work/gpc-artifacts/rehost-log-proof.json`.

`v2dll.log` дописывается и содержит смешанные CP1251/UTF-8 строки прежних PID.
Контроллер сохраняет исходный raw `.full.log`, выделяет строки только текущего
PID и пишет UTF-8 журнал проверки. Числовой протокол GPC целиком ASCII;
невалидные байты русской диагностики не участвуют в сравнении состояния.

Открыты: native выбор опции и проверка GPC enabled.
Рабочая базовая партия не считается приёмкой самого GPC-модуля.
