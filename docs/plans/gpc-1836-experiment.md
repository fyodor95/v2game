# Проверка Пруссии и Австрии со старта 1836 года

Дополнение к [исходному плану](great-power-culture-cores.md) по запросу пользователя
16 ноября. Производственные настройки и правила механики не меняются.

## Условия и ожидаемый результат

PRU имеет primary `north_german`, AUS — `south_german`. Признанные культуры
не участвуют. В истории обеих стран отсутствует `nationalism_n_imperialism`;
технология имеет год 1850. До её получения выдача этим странам должна быть пустой,
даже при срабатывании общего планировщика.

После выдачи технологии только PRU/AUS ожидаются корки на чужих провинциях,
где соответствующая основная культура входит в множество крупнейших по сумме
всех POP. Собственные провинции и существующие корки исключаются. «Все немецкие
провинции» без этих условий не являются ожидаемым множеством.

## Стадия 1: базовое состояние

В изолированной копии начать настоящий сценарий 1836 за Пруссию. Сохранить
базовый сейв под новым именем, получить native snapshot с текущими GP,
технологиями и культурами. Проверить исходные SHA и отсутствие технологии.
Для однократного старта допустим разрешённый Python GUI с проверкой целевого
окна; дальнейшие действия выполняются через CLI. Перед запуском — отдельные
userdata, кэш, логи, autosave NEVER, master/music/FX/ambient 0.

## Стадия 2: отрицательный контроль

Только в тестовом INI включить ускоренный профиль. Дождаться настоящего
производственного callback, записать дату, pass, RNG, список уведомлений и
preview. У PRU/AUS не должно быть добавлений без технологии. При принудительном
debug-проходе явно отличать его от срабатывания планировщика.

## Стадия 3: технология и точная выдача

Одним изолированным triggered event выдать `activate_technology` только PRU/AUS.
Сохранить состояние до выдачи корок. Независимый Python oracle определяет GP
и технологически подходящих получателей по подтверждённому native snapshot;
население и существующие корки читает из сейва.

Продвинуть симуляцию до ускоренного срабатывания. Сохранить после, сравнить
точное множество всех добавленных пар, отсутствие удалений, лишних корок и
оставшихся кандидатов. В журнале должен быть один общий pass для обеих стран;
русское уведомление — только получателям с положительным результатом.

## Стадия 4: повтор и восстановление

Повторный проход на неизменном мире должен быть пустым. Загрузка результата
новым процессом должна сохранить корки и расписание без повторной инициализации.
Восстановить точные байты исходного тестового INI. Крупные сейвы/логи — в `.work`,
в Git — только fixture, план и отчёт с хешами и результатами.

Нативная ошибка или неизвестный результат команды прекращают сценарий без
автоматического повтора мутаций. Ошибка GUI-фокуса прекращает физический ввод.
