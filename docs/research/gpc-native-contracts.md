# Нативные контракты национальных провинций великих держав

Дата исследования: 15 ноября 2026 года. Область: статическое исследование выдачи `add_core`, действующих великих держав и технологии `nationalism_n_imperialism`. Исследование не запускало игру, не изменяло `.work`, сборки или Git.

## Версия и уровень доказательств

Исследован `D:/v2game/v2game.exe`, SHA-256 `62d48c204364dd706584777c2e2b3c7ab3c5f1dd0170872554943575d53d6648`, Windows x86, Victoria II: Heart of Darkness 3.04. Использованы PE-байты этого файла и `.work/creatinecore/game-disassembly.txt`. Номера строк ниже относятся к этому существующему дизассемблированию, а не к исходникам движка.

Адреса `VA` относятся к базе `0x00400000`. При выполнении адрес вычисляется как действительная база образа плюс `RVA = VA - 0x00400000`. Указатели в таблицах виртуальных функций также подлежат релокации. Проверка начальных байтов подтверждает версию участка, но не заменяет runtime-проверку ABI, фазы и результата.

Статически найдена полная цепочка `add_core` до изменения обеих сторон связи. Также найдены точные поля настоящего GP-статуса и изученных технологий. Никакой из этих контрактов в настоящем отчёте ещё не объявляется проверенным запуском игры.

## 1. От `add_core` к исполнителю

Регистрация ключа расположена в `00C3F3BC..00C3F3D8` (строки 2755210–2755216): строка `add_core` по адресу `00E23F08` получает token `0x2AB`.

Фабрика эффектов `00876B30` (строка 1438054) обрабатывает диапазон через таблицы:

1. Индекс ключа: `0x2AB - 0x1BF = 0xEC`.
2. Байт таблицы `00878DC0[0xEC]` равен `13`.
3. Элемент `00878D80[13]` равен `00876C24`.
4. Ветка `00876C24..00876C64` выделяет `0x2C` байт и ставит vtable `00E2A928`.
5. Слот 11 этой vtable, по PE-байтам `00E2A954`, содержит `0087E760` — исполнитель эффекта. Слот 7 содержит парсер `0087E6F0`.

Парсер `0087E6F0` (строка 1448265) хранит разрешённую пару страны в `effect+0x20/+0x24`, числовую провинцию — в `effect+0x28`; признаки специальных scopes находятся в `+0x1C/+0x1D`. Для обычного тега он вызывает существующий resolver `0055C6C0`. Эти детали нужны для доказательства происхождения исполнителя; создавать искусственный объект эффекта ради выдачи не требуется.

Исполнитель `0087E760` (строка 1448315):

- Имеет `ECX=effect`, два стековых аргумента и `ret 8`.
- Берёт текущую пару страны из `context+8/+0x0C`; переопределяет её тегом эффекта либо специальным scope.
- Берёт индекс провинции из `effect+0x28`, а при нуле — из `context+0x10`; разрешает `province*` через `world+0xACC`.
- В `0087E867..0087E885` проверяет существующую корку по `countryID` в элементах размером 8 байт из `province+0x148..+0x14C`.
- Только для отсутствующей корки в `0087E887..0087E88F` делает `push 1; push identityPair; push province; call 004B61A0`.
- После вызова в `0087E894..0087E8A4` разрешает страну и **отдельно** записывает `country+0x1434 = 1`.

Последняя запись не входит в mutator. Обёртка нового модуля обязана воспроизвести её после фактического добавления, чтобы соответствовать штатному эффекту. Точное имя внутреннего флага пока не установлено; здесь он обозначается как наблюдаемый байт инвалидирования, без приписывания неподтверждённого назначения.

## 2. Операция выдачи: `004B61A0`

### Входной контракт

Начало — строка 233765; `RVA 0x000B61A0`.

```cpp
struct CountryIdentity {
    uint32_t packedTag;
    int32_t countryIndex;
};

// Статически установленный ABI; возвращаемое значение не определяет успех.
using AddCoreFn = void (__stdcall*)(
    void* province,
    const CountryIdentity* recipient,
    int recordHistory);
```

Аргументы читаются из `[EBP+8]`, `[EBP+0x0C]`, младшего байта `[EBP+0x10]`. Эпилог `004B6283` — `ret 0x0C`. Входных скрытых аргументов через `ECX/ESI/EDI` в полном теле функции не обнаружено. `EBX/ESI/EDI/EBP` сохраняются. Это отличается от её внутренних вспомогательных функций, имеющих нестандартные регистровые аргументы: вызывать их самостоятельно не требуется.

Пара страны — два последовательных 32-битных слова, а не указатель на современный `std::string`. У объекта страны соответствующие значения находятся в `country+0x1C` и `country+0x20`. Mutator копирует пару, а не сохраняет указатель на временный аргумент. При вызове надо проверить соответствие тега, ID и записи в менеджере стран; не конструировать ID из текстового порядка файлов.

### Наблюдаемые изменения

1. `004B61B1..004B61DE` повторно проверяет наличие `countryIndex` в векторе корок провинции. При наличии сразу выходит.
2. При ненулевом `recordHistory` (`004B61E4..004B6256`) создаёт native history entry через `005F46B0/005F46F0`, устанавливает текущую дату мира и вставляет его в историю `province+0x60` через виртуальный слот 6. Штатный скриптовый `add_core` передаёт `1`.
3. `004B6259..004B625B` вызывает `004D61D0`: `EAX=identityPair`, `EDI=province+0x148`. Эта функция (строка 275970) добавляет оба слова в native vector и увеличивает `end` на 8. При необходимости используется игровой аллокатор.
4. `004B6260..004B6278` разрешает страну через менеджер `*[012587E4]`, читает `provinceID` из `province+0x58` и вызывает `0050E2D0` с `ESI=country`, `provinceID` в стеке.
5. `0050E2D0` (строка 347166) проверяет повтор и добавляет провинцию в обратный список `country+0x9F8`; `+0x9FC` — хвост, `+0xA00` — количество. Узел: значение `+0`, предыдущий `+4`, следующий `+8`, служебный байт `+0x0C`.

Следовательно, запись только в `province+0x148` недостаточна. Найденный mutator обслуживает вектор провинции, обратный список страны и историю; native effect дополняет его записью `country+0x1434`.

### Независимые вызывающие участки

Помимо исполнителя эффекта обнаружены:

- `004A9C77` (строка 221126): загрузочная ветка разрешает тег через `0055C6C0` и вызывает mutator с `recordHistory=0`.
- `005F48A7` (строка 641063): применение history entry вызывает ту же функцию с `recordHistory=0`.
- `005F4B64` (строка 641284): обратная ветка истории также вызывает её с `0`.

Эти вызовы независимо подтверждают порядок трёх аргументов и различие обычной игровой выдачи от воспроизведения истории.

### Проверка результата и отказы

`EAX` не является документированным статусом: ветки выходят с разными промежуточными значениями. После вызова нужны проверка ровно одной пары в векторе провинции и ровно одного `provinceID` в обратном списке страны. Для отсутствовавшей пары дополнительно воспроизводится запись `country+0x1434=1`.

До вызова необходимо проверить весь набор провинций/стран, живой мир, диапазоны и согласованность указателей. Вызывать на подтверждённом потоке симуляции, а не из IPC-потока. Часть функции создаёт историю раньше изменения остальных контейнеров; транзакционность или безопасный откат при исключении не установлены. При ошибке нельзя объявлять успех, автоматически повторять или пытаться восстанавливать связь прямыми записями.

Дублированная выдача штатно не изменяет контейнеры; это надо подтвердить runtime, включая отсутствие второго history entry и уведомления.

## 3. Настоящие великие державы

### Доказательство через штатный trigger

`is_greater_power` по адресу строки `00E1E7C0` зарегистрирован как token `0x86F` в `00C4F15A..00C4F176` (строки 2768494–2768500).

Фабрика triggers `008B33E0` для диапазона от `0x798` использует байты `008B6794` и указатели `008B66F4`. Для `0x86F` получается индекс 16 и ветка `008B4DF9` (строка 1518060). Она вызывает конструктор `008B7520` (строка 1521785), устанавливающий vtable `00E31CE8`. Слот 6 `Evaluate` этой vtable содержит `008EE1F0`.

`008EE1F0` (строка 1586973) разрешает страну из scope, затем сравнивает **байт `country+0x31`** с требуемым булевым значением в `trigger+0x1C`. В прямом страновом scope это `008EE23D..008EE24F`; для POP scope сначала берётся владелец провинции. Рейтинг, число восемь или порог score в этой проверке не участвуют.

Это непосредственно подтверждает чтение `country+0x31 != 0` как текущий GP-статус. Подмена на `rank<=8` неверна, в том числе при переходном состоянии или изменённом числе держав.

### Текущий список и существование

В `0068C660` (строка 823295) видна операция перехода GP-статуса:

- `0068C6FC..0068C703` вызывает установку статуса `0053D680` с `AL=1`; `0053D68C` пишет его в `country+0x31` (строка 404462).
- `0068C71F..0068C75A` снимает флаг прежнего GP и удаляет его из вектора `world+0xBE0`.
- `0068C798..0068C81C` добавляет новую страну в этот же вектор.
- `0068D2CC..0068D338` при полном перестроении очищает статусы элементов вектора и сам вектор.

Список GP — native `vector<country*>`: `world+0xBE0` begin, `+0xBE4` end, `+0xBE8` capacity. Его размер берётся по указателям; жёсткого ограничения восемью в новом коде не требуется.

Рекомендуемое чтение: на завершённой согласованной фазе получить текущий GP-вектор, проверить каждый указатель по менеджеру стран и ID, наличие `country+0x31`, а также существование страны. Последнее можно сопоставить с native living vector `world+0xADC/+0xAE0` и наличием собственных провинций в `country+0x9D8/+0x9DC`. Штатный event loop в `008A7D70..008A7D9E` также пропускает нулевую identity и пустой вектор провинций. Точная политика нативного `exists` и согласованность GP/living в выбранной фазе ещё проверяются runtime; противоречивый снимок нельзя молча «чинить» пересчётом рейтинга.

Список после чтения сортируется по `countryIndex`; порядок native vector не должен определять порядок мутаций.

## 4. Наличие и изучение `nationalism_n_imperialism`

### Поиск технологии по имени

В EXE есть явная ссылка на эту технологию: `0084C4B9..0084C52E`, начиная со строки 1379559. Это независимый нативный образец, использующий точное имя `nationalism_n_imperialism`:

1. Создаёт старую игровую строку длиной `0x19` по адресу литерала `00E276F0`.
2. Берёт менеджер технологий из `*[0125EADC]`.
3. Передаёт `EAX=manager+0x10`, в стеке `GameString*`, и вызывает `0057B0A0`.
4. Получает `technology*` либо ноль в `EAX`.

Такой же lookup выполняет generic trigger factory: `008B5C49..008B5C8E` (строки 1519008–1519032). При найденной технологии он создаёт условие через `008C5C00`.

Lookup `0057B0A0` (строка 484278) имеет нестандартный ABI: **таблица в `EAX`, один указатель на строку в стеке, `ret 4`**. Он хеширует имя и сравнивает с native GameString `technology+0x2AC`, обходя цепочку коллизий. Нужна x86 asm-обёртка с явной передачей `EAX`; обычный `thiscall(manager, name)` неверен.

GameString здесь имеет старый MSVC layout: union из 16 байт inline data/указателя, длина `+0x10`, capacity `+0x14`. Для имени из 25 байт SSO недостаточно: нельзя записать его в 16-байтный inline buffer. Использовать существующий квалифицированный адаптер игровых строк/аллокатора; не передавать современный STL-объект.

Функция `00576F80` получает менеджер, но при его отсутствии создаёт его (`00576FA2..00576FCD`). Для read-only snapshot после загрузки предпочтительно читать уже существующий глобальный указатель; отсутствие manager/table — ошибка готовности мира, а не доказательство отсутствия нужной технологии. Нулевой результат **валидного lookup в загруженном наборе данных** означает отсутствие технологии и снимает технологический фильтр согласно плану.

### Изученность у страны

Generic technology trigger имеет vtable `00E30580`; его `Evaluate` — `008C5C30` (строка 1539010):

```text
techState = *(country + 0xBCC)
levels    = *(techState + 0x2B8)
techIndex = *(technology + 0x2E4)
result    = levels[techIndex] >= wantedLevel
```

Нативная проверка именно nationalism в `0084C5AB..0084C5BD` (строки 1379622–1379625) использует те же поля и сравнивает с `1`. Это непосредственно подтверждает условие «изучена», без предположения о фиксированном номере технологии.

В деструкторном участке `0096BD3E..0096BD5D` (строки 1742700–1742708) видно освобождение массива и обнуление `+0x2B8/+0x2BC/+0x2C0`, что согласуется с native vector begin/end/capacity. До чтения нового кода нужны проверки диапазона `techIndex`, кратности и границ массива, а также соответствия объекта найденному имени. Проверки размерности массива в самой штатной trigger-функции нет: это не основание обходить валидацию нового моста.

Менеджер, указатель технологии, её индекс и techState нельзя переносить между загрузками. Найденный индекс относится к текущему набору данных, а не к общему формату Victoria II.

## 5. Начальные сигнатуры исследованных функций

Байты прочитаны непосредственно из PE. Это кандидаты проверок версии, а не готовая политика совместимости перехватов.

| Назначение | VA | RVA | Первые 16 байт |
|---|---|---|---|
| Mutator добавления core | `004B61A0` | `000B61A0` | `55 8B EC 81 EC 10 01 00 00 53 8B 5D 0C 56 8B 75` |
| Исполнитель `add_core` | `0087E760` | `0047E760` | `55 8B EC 83 E4 F8 83 EC 14 53 56 57 8B 7D 08 8B` |
| `is_greater_power` Evaluate | `008EE1F0` | `004EE1F0` | `55 8B EC 83 EC 08 56 8B 75 08 57 8B F9 8B 4E 14` |
| Lookup технологии | `0057B0A0` | `0017B0A0` | `55 8B EC 51 8B 4D 08 53 56 8B F0 8B 41 14 57 89` |
| Technology trigger Evaluate | `008C5C30` | `004C5C30` | `55 8B EC 83 EC 08 8B 45 08 8B 50 08 8B 40 0C 56` |

Если другой разрешённый модуль уже перехватил участок, несовпадение сигнатуры не даёт разрешения перезаписывать его. Для непосредственного вызова нужен подтверждённый маршрут к текущему оригиналу/согласованной обёртке. Адреса вспомогательных контейнерных функций не предлагаются как публичный API.

## 6. Обязательные runtime-проверки перед интеграцией

1. На квалифицированной simulation phase сравнить snapshot GP-вектора и `country+0x31` с настоящим trigger `is_greater_power`. Включить страну высокого ранга без GP-статуса, изменение статуса и тестовое число GP, отличное от восьми.
2. Сопоставить наличие и уровень nationalism с native script trigger для изучившей/не изучившей страны; отдельный набор данных без этой технологии. Ошибка lookup или пустой менеджер не должна превращаться в снятие фильтра.
3. На маленьком fixture сравнить штатный `add_core` и новый mutator wrapper: точное множество пар, обратные списки, история, байт `+0x1434`, отображение в GUI, сохранение и повторная загрузка.
4. Повторить выдачу той же пары и убедиться в отсутствии дубликатов, лишней истории и уведомления.
5. Проверить чужую оккупированную провинцию: меняется core указанного получателя, юридический владелец/контролёр не меняются.
6. После сохранения проверить `core=` в `.v2`, затем загрузить новым процессом и сверить обе стороны связи, а не только изображение карты.
7. На настоящих host/client выполнить одну выдачу в одинаковой фазе: одинаковые отсортированные core-пары, history/state digest и отсутствие дополнительных команд из каждого клиента. Само отсутствие OOS-окна не доказывает совпадение контейнеров.
8. Проверить неподходящий EXE, отсутствие обязательной сигнатуры, неготовый мир и устаревший snapshot. Отказы должны быть явными; runtime-ошибку после частичного применения нельзя объявлять атомарным отказом.

Границы данного этапа: настоящая simulation phase и её кратность, состояние scheduler, native RNG, разрешение ничьей культур и доставка уведомления исследуются отдельно. Их корректность не следует из найденного ABI `add_core`.
