# Нативное сохранение хостом при общей паузе

Исследование 15 ноября 2026 года для точного Victoria II 3.04 x86,
SHA-256 EXE `62d48c204364dd706584777c2e2b3c7ab3c5f1dd0170872554943575d53d6648`.
Адреса VA приведены для базы `00400000`; адаптер использует RVA и runtime base.
Исследователь не выполнял сборок, запусков, GUI-действий и изменений `.work`.

## Квалифицированный путь

Существующий SP helper `save-native` уже использует native `00675A80`:
`ECX = GameString*` с VFS-путём, один stack argument `CInGameIdler*`, `ret 4`
на `00675BD4`. Это штатная UI-операция сохранения, а не чистая функция сериализации.

В `00675AD8..00675AF2` она включает рабочий индикатор; в
`00675B11..00675B46` создаёт native file через `00992740`, в
`00675B70..00675B85` вызывает world virtual serializer `vt+4`. После закрытия
writer и выключения индикатора она всегда вызывает `0066EEE0` на idler
(`00675BBD..00675BBF`). Последний метод переключает внутриигровое меню.

Нативный save не возвращает надёжный boolean успеха: обработчик ошибки может
показать штатный диалог и завершить вызов. Поэтому возврат функции не доказывает
валидность `.v2`. Адаптер проверяет создание непустого файла и состояние игры;
Driver затем разбирает сохранение, проверяет дату/содержимое и перезагрузку.

## Побочные действия меню

`0066EEE0` при скрытом меню открывает его и сохраняет старую паузу в
`idler+0x1E04`. В `0066EF25..0066EF44` вызов pause action разрешён только SP.
Однако в конце open-ветви `0066EFED..0066F027` есть отдельная обработка modal
`idler+0x1E00`, способная вызвать pause action без такого MP-ограничения.
Нельзя безусловно считать произвольный вызов toggle безопасным для общей паузы.

Если меню `*(idler+0x1D24)` уже visible (`+0x67 != 0`), `0066EEE0` вызывает
`0066F060`. Этот close-путь в `0066F1EF..0066F206` явно запрещает автоматическое
снятие паузы при `idler+0x5C != 0`. Поэтому выбран узкий контракт:

- `OpenSaveMenu(base)` отдельно открывает настоящее меню только при чистом UI.
- `Save(base,name)` принимает только уже открытое меню и вызывает полный
  `00675A80`, который штатно закрывает его после записи.
- Прямой serializer, ручное изменение pause/menu flags и физический ввод
  не используются.

Чистый UI проверяется по тем же источникам, которые использует native menu:

| Источник | Проверка |
|---|---|
| `idler+0x1D80` | Ноль; getter `vt+0x144 = 006786E0` проверяет это поле |
| `[idler+0x1E00]+0x28` | Modal window скрыт по `+0x67` |
| `[idler+0x1D24]` → `menu_save`, slot `0x6C` | Save-dialog скрыт |
| То же → `menu_message_settings` | Диалог настроек сообщений скрыт |
| `[idler+0x718]+0x30`, если существует | Дополнительное окно скрыто |
| `[idler+0x1D68].vt+0x0C`, если существует | Штатный UI getter возвращает false |

Последние четыре проверки повторяют predicates `0066F060..0066F143`, чтобы
обычный close-путь не превратился в закрытие вложенного диалога и повторное
открытие меню. Native `OpenSaveMenu` вызывается только на потоке владельца.
После него повторно проверяются MP host, пауза, дата и фактическая видимость меню.

## Предусловия сети и сохранность файлов

Driver обязан подтвердить общую паузу и одинаковую дату на обоих участниках.
Адаптер дополнительно использует квалифицированный `vic2_mp::Inspect` и требует:
`mode==1`, host, `network_ready`, `paused`, отсутствие исполняемой команды.
Клиент сохранять этим интерфейсом не может. Адаптер не посылает сетевую паузу
и не снимает её после сохранения.

Имена ограничены 1–15 ASCII-символами `[A-Za-z0-9_-]`, без расширения. Реальный
путь строится точно по изоляции существующего `save-native`: EXE должен находиться
в `.work/.../game`, результат — соседний `userdata/save games/<name>.v2`.
Native writer получает VFS-путь `save games/<name>.v2`. Проверка перенаправления
userdata перед запуском остаётся обязательным предусловием Driver.

Существующий путь отвергается до создания native string и повторно непосредственно
перед writer. Отсутствие проверяется отдельно от ошибок доступа/каталога. Driver
владеет каталогом тестовой сессии и не допускает параллельных записей под этим
именем: штатный writer сам не предоставляет атомарного режима create-new.
Оригинальные пользовательские сохранения никогда не являются целью адаптера.

Native GameString создаётся `00409350` и уничтожается `00408AD0`, с native
allocator ownership. Освобождение через CRT плагина не используется. После save
повторно подтверждаются тот же world/idler, MP host, пауза, дата и закрытие меню.
Результат содержит путь, размер и дату. Исключение native вызова либо несоответствие
после него означает неопределённый исход: повторять save автоматически нельзя.

Граница изменения состояния проходит непосредственно перед входом в
`InvokeMenu`/`InvokeSave`. Любое исключение или отрицательная проверка после этой
границы, включая повторный `Require`, освобождение native string, проверку
существования/размера файла и формирование успешного результата, выходит только
с внешним кодом `E_MP_SAVE_NATIVE_OUTCOME_UNKNOWN`. Исходная причина сохраняется
после двоеточия для диагностики. Мост обязан пометить сессию `poisoned`; Driver
не должен повторять операцию. В частности, `E_MP_BUSY` после вызова не является
отказом до отправки, а `E_MP_SAVE_MISSING`/`E_MP_SAVE_EMPTY` после writer не
доказывают отсутствие его побочных действий. Ошибки предусловий до этих вызовов
сохраняют прежние коды. Последняя проверка отсутствия файла перед writer также
остаётся предусловием, если успешно освобождена только приватная native string.

Узкое ревью `mp_events.h` аналогичного дефекта не выявило: `Current` с
`executing`-проверкой выполняется до первой записи `TryPick`; после неё состояние
окна проверяется внутри SEH-защищённого helper. Отказ helper уже выдаёт
`E_MP_NATIVE_CALL`, который запрещает повтор и приводит к `poisoned` в мосте.

## Реализация и проверки

Добавлен `tools/vic2test/native/mp_save.h`, namespace `vic2_mp_save`:

```cpp
Result OpenSaveMenu(DWORD base);
Result Save(DWORD base, const char* name);
```

`Result`: `completed`, `menu_open`, `already`, `date`, `bytes`, `path`.
Это не команда очереди: запись синхронная, `completed` устанавливается после
возврата writer и перечисленных проверок. Полная пригодность `.v2` подтверждается
отдельным независимым разбором и повторной загрузкой.

Побайтно сверены семь сигнатур, релокируемый SEH handler save и относительная
цель его завершающего menu call. Проверки реализованы относительно runtime base.
Статическое ревью охватывает ABI, native string ownership, ветви menu/pause,
пути файлов и ошибочные исходы. Сборка и настоящая runtime-проверка выполняются
главным агентом: общая пауза до/после, отсутствие изменения даты, отказ клиента,
отказ перезаписи, непустой parseable `.v2`, перезагрузка и перехост.
