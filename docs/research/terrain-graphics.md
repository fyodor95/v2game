# Сборка текстур местности

Исходники находятся в `assets/terrain/variants/00.png` … `51.png`, соответствие типов номерам хранится в `assets/terrain/tiles.json`. Каждый PNG — квадратная композиция 2×2 из четырёх разных художественных вариантов одной местности. Порядок вариантов: верхний левый, верхний правый, нижний левый, нижний правый.

`tools/terrain_map.py` только разрезает квадранты, конвертирует RGB и масштабирует каждый вариант до 256×256. В атласе 4096×4096 размещены 64 ячейки 512×512; каждая используемая ячейка содержит четыре варианта. Прочие ячейки сохраняют исходную графику, увеличенную до 512×512. Шейдер плавно смешивает четыре квадранта внутри соответствующей типу ячейки.

Исходник должен иметь чётную сторону не меньше 512 пикселей. Упаковщик проверяет состав категорий, целые уникальные номера 0…63, все исходные PNG, уникальность всех 208 используемых вариантов, русские названия, назначения провинций и исходные форматы до записи результатов. Один PNG на тип облегчает ручную проверку различимости четырёх вариантов; точное отличие хешей само по себе не доказывает художественную различимость.

Для воспроизводимой сборки нужны Pillow и NumPy (для CPU-превью шейдера). В изолированном стенде использованы Pillow13 и NumPy2.5.4; установка выполнена только в `.work/terrain/python`. Исходный `terrain.bmp` передаётся через `--baseline`; рядом ожидаются `terrain.baseline.txt` и `texturesheet.baseline.tga` из исходной версии. Пример:

```powershell
python -m pip install --target .work/terrain/python -r tools/requirements-terrain.txt
$env:PYTHONPATH = (Resolve-Path .work/terrain/python).Path
python tools/terrain_map.py --baseline .work/terrain/terrain.baseline.bmp --check-only
python tools/terrain_map.py --baseline .work/terrain/terrain.baseline.bmp
```

Если локальной исходной копии нет, три контрольных файла восстанавливаются из Git без смены ветки или индекса. Следующий код Python использует архив исходного коммита с правилами переносов строк репозитория:

```python
from io import BytesIO
from pathlib import Path
import subprocess
import tarfile

revision = 'ed4c7ac427bef98ac95734202c6146a27047ed54'
mapping = {
    'map/terrain.bmp': 'terrain.baseline.bmp',
    'map/terrain.txt': 'terrain.baseline.txt',
    'map/terrain/texturesheet.tga': 'texturesheet.baseline.tga',
}
archive = subprocess.check_output(['git', 'archive', revision, *mapping])
destination = Path('.work/terrain')
destination.mkdir(parents=True, exist_ok=True)
with tarfile.open(fileobj=BytesIO(archive)) as source:
    for name, target in mapping.items():
        path = destination / target
        if not path.exists():
            path.write_bytes(source.extractfile(name).read())
```

Результаты: `map/terrain/texturesheet.dds` и `texturesheet2.dds` в формате DXT1, `terrain.bmp`, графические соответствия `terrain.txt` и русская легенда `assets/terrain/legend.png` со всеми четырьмя вариантами каждого типа. В `.work/terrain` создаются `comparison.png` (первый старый слот соответствующего типа рядом с новым составным рендером), `repeats/` с контрольными изображениями и `texture-validation.json` с номерами, хешами источников и отдельных вариантов. Для категории без старого графического соответствия сравнение явно указывает отсутствие исходной текстуры.

`--atlas-only` собирает атласы и контрольные изображения без записи игровой карты и таблицы графических соответствий; этот режим предназначен для промежуточной проверки. `--check-only` не записывает результаты.

Вода, морские провинции и неизвестные цвета границ сохраняют исходные растровые индексы. Назначения берутся только из однозначных явных `terrain` исторических файлов.


## Проверка непрерывности и фактический шейдер

Обычный повтор PNG не является способом отображения финального шейдера. Для разрушения регулярной решётки применены детерминированный аналитический value-noise, плавное искажение общих мировых координат и разные повороты, масштабы и фазы каждого варианта. Источник точных коэффициентов — `gfx/FX/terrain_2_0.fx`; CPU-реализация в сборщике воспроизводит эти формулы отдельно через NumPy float32:

- `TerrainHash`: двойная целочисленная перестановка `(n × 34 + 1) × n mod289`, затем деление на 289;
- `TerrainValueNoise`: билинейное смешивание четырёх хешей с кубическим `t²(3−2t)`;
- исходные координаты `p = world/16`, две частоты и фазы шума для искажения `p += (warp−0.5)×0.65`;
- повороты 17°,73°,137°,221°, масштабы 0.91,1.07,1.19,0.87 и отдельные фазовые смещения;
- зеркальная адресация каждого рисунка с полутексельным clamp внутри собственного 256-пиксельного квадранта;
- два дополнительных шумовых поля для весов смешивания, контраст 1.8, saturate и кубический smoothstep.

Текстурные выборки четырёх вариантов сохраняются; вычисление координат и весов использует арифметику. CPU-превью использует float32 для вычислений, билинейную выборку и финальное округлениеRGB в 8 бит. Оно иллюстрирует поверхность одного типа без colormap, переходов между типами, освещения, зимы и тумана войны. Отличия округления CPU/GPU и сжатияDXT1 оцениваются отдельными GUI-контролями; битового совпадения не заявляется.

В `repeats/` сохраняются отдельные `*-mirrored.png` и общий `*-shader-composite.png` на область 128×128 мировых единиц. Первые используют один рисунок во всех четырёх каналах и тот же алгоритм координат/смешивания, вторые — все четыре художественных варианта. `comparison.png` показывает рядом со старым первым слотом новый составной рендер.

Исходные сетки 3×3 сохраняются в `repeats/raw-diagnostic/`, чтобы честно показывать швы обычного повтора. JSON включает среднее различиеRGB противоположных краёв каждого PNG. Нулевое различие краёв не является полной проверкой художественной бесшовности, а ненулевое не означает разрыв при зеркальной выборке.

Локальные CPU-контроли обновлённой формулы: известные значения permute289, совпадение value-noise с хешем в целочисленных узлах, непрерывность шума возле границ ячеек, float32-координаты в пределах 0…255 и веса 0…1. Независимая сверка с отдельным скалярным double-evaluator на 1024 точках области 5632×5632 дала максимальное расхождение UV7.22×10⁻⁵ (около 0.019 текселя) и весов 1.36×10⁻⁵; это соответствует различию float32/double. Четыре примера для полей, леса, гор и джунглей сохранены в `.work/terrain/chaos-preview/`; исходные художественные PNG и игровые атласы при подготовке этих примеров не менялись.

## Формат атласов: DDS DXT1

Проверка настоящего окна игры выявила зависимость от формата: TGA2048 отображается, TGA4096 даёт чёрную поверхность, а DDS4096 с исправленным заголовком отображается. В этих проверках использовался идентичный шейдер. Статичный контроль типа 08 сохранён в `.work/terrain/atlas-retained-dds4096.png`; полный шейдер плавного смешивания с DDS — в `.work/terrain/final-dds-full.png`. Форматные образцы находятся в `.work/terrain-format-probes/`. Вероятна особенность загрузчика TGA движка, но конкретный предел не исследован. Сборщик выпускает рабочий формат DDS DXT1.

Для 4096×4096 DXT1 размер блока данных составляет 8 388 608 байт, полного файла —8 388 736 байт (8 МиБ плюс 128 байт заголовка). Два атласа занимают около 16 МиБ. Несжатый RGB TGA4096 содержит около 48 МиБ пиксельных данных на один файл; Конкретный предел загрузчика и видеопамяти не установлен.

Pillow13 записывает для сжатого DDS поле `dwPitchOrLinearSize`, не соответствующее ожидаемому здесь размеру полной поверхности. Сборщик исправляет DWORD по смещению 20 на 8 388 608, устанавливает `DDSD_LINEARSIZE` и снимает `DDSD_PITCH`. FourCC остаётся `DXT1`, mipmap-цепочка не создаётся. Затем файл полностью декодируется для проверки размера, формата и уникальности 208 используемых вариантов.

DXT1 сжимает с потерями: точное совпадение RGB исходника и декодированного DDS не требуется. JSON сохраняет отдельные хеши исходных PNG, вариантов RGB, полного сжатого DDS, декодированного атласа и каждого декодированного варианта. Хеши различимости исходников проверяются до сжатия; декодирование и отдельные проверки рисунков контролируют сохранение вариантов после сжатия.

Публикация сначала записывает обе DDS во временные файлы в проверенном каталоге `root/map/terrain`, синхронизирует и проверяет байты, затем атомарно заменяет каждый конечный DDS. Только после успешной записи и проверки обеих копий удаляются два устаревших производных файла `texturesheet.tga` и `texturesheet2.tga`. Другие файлы не удаляются; симлинки и пути вне root отклоняются. Резервный исходный TGA в `.work/terrain` сохраняется.

Функции кодирования и публикации проверены на отдельной синтетической RGB4096-фактуре в `.work/terrain-autogen-build/dds-test`: размер заголовка, FourCC, длина, декодирование, идентичность двух DDS, удаление только заданных TGA, сохранение постороннего файла и очистка временных файлов прошли. Эта проверка не запускает игру и не заменяет контроль итоговых художественных текстур.
