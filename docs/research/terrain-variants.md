# Четыре нерегулярно смешиваемых рисунка каждого типа

`gfx/FX/terrain_2_0.fx` сохраняет 64 графических индекса движка и сетку атласа 8×8. Атлас 4096×4096 содержит ячейки 512×512, в каждой четыре самостоятельных рисунка по 256×256 в порядке TL, TR, BL, BR. Рабочий контейнер этой сборки — DDS; успешно работающая загрузка DDS проверяется общей GUI-квалификацией. Прежний TGA4096 не обеспечивал корректную загрузку текстуры этой игрой, несмотря на поддержку размера видеокартой.

## Нерегулярность и непрерывная поверхность

Расположение рисунков зависит от общей мировой позиции, без ID провинций, кадрового случайного выбора или анимации. Для суши и берега используется одна и та же мировая координата `vTexCoord0` с исходным масштабом `/16`.

Чтобы зеркальные отражения четырёх рисунков не складывались в общий повторяющийся орнамент, введены:

- гладкое искажение координат двумя независимыми полями value noise;
- разные фиксированные углы, масштаб и фаза каждого рисунка;
- отдельные гладкие шумовые поля весов вместо прежнего общего треугольного цикла128.

Каждый рисунок по-прежнему зеркально повторяется и ограничивается полутекселем. **PNG не обязан быть попиксельно периодическим: непрерывность цвета обеспечивает адресация шейдера.** Зеркалирование может давать излом производной отдельного мотива, но раздельные оси, фазы и плавное искажение снижают заметность регулярной сетки.

### Точные параметры

Начальная координата `p = world / 16`. Обозначим `N(p)` описанный ниже value noise:

```text
warp.x = N(p * 0.21  + (3.7, 9.2))
warp.y = N(p * 0.173 + (21.3, 6.4))
p += (warp − 0.5) * 0.65
```

Уже искажённая `p` поворачивается, масштабируется и сдвигается отдельно для каждого варианта:

| Вариант | Угол | Масштаб | Фаза |
|---|---:|---:|---|
| TL | 17° | 0.91 | (0.13, 1.71) |
| TR | 73° | 1.07 | (2.23, −0.41) |
| BL | 137° | 1.19 | (−1.37, 3.11) |
| BR | 221° | 0.87 | (4.73, 2.61) |

Затем для каждой пары координат `r`:

```text
uv = 1 − abs(frac(r * 0.5) * 2 − 1)
uv = clamp(uv / 16, 0.5 / 4096, 1 / 16 − 0.5 / 4096)
```

К `uv` добавляются начало графической ячейки и начало соответствующего квадранта. Отступ предотвращает подмешивание соседнего варианта линейной фильтрацией.

Веса рассчитываются из искажённой `p`:

```text
q.x = N(p * 0.137 + (9.3, 4.7))
q.y = N(p * 0.119 + (31.1, 17.9))
q = saturate((q − 0.5) * 1.8 + 0.5)
q = q² * (3 − 2q)
```

Итог — `lerp(lerp(TL,TR,q.x),lerp(BL,BR,q.x),q.y)`. Одни и те же четыре адреса и веса применяются ко всем четырём соседним индексам местности, после чего сохраняется исходное шумовое смешивание типов. Граница провинции не переключает фазу или вариант.

### Value noise

В четырёх целочисленных углах клетки вычисляется hash, затем значения интерполируются по обеим осям с `t²(3−2t)`. Перестановка `P(n) = ((34*n+1)*n) mod 289`; hash равен `P((P(y mod289)+x) mod289)/289`. Используется остаток через `floor`, корректный для отрицательных координат. Никаких дополнительных выборок текстур или `sin` нет.

Промежуточные целые значения перестановки помещаются в точное целочисленное представление fp32; модульные операции отдельно проверены на всех289входах. Сам hash имеет конечный период289клеток, но разные масштабы и фазы полей устраняют прежний общий цикл128единиц; отдельные поля повторяются за пределами обычного размера карты.

## Компиляция и аппаратная совместимость

Четыре подробные техники используют парные `vs_3_0` и `ps_3_0`. Аппаратная пара VS1.1+PS3 недопустима по [документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/shader-model-3). Обзорные Low и остальные техники сохранены.

Полный FX успешно компилируется Windows SDK10.0.26100 `fxc.exe /T fx_2_0`; отдельные функции — с `/O3`:

| Техника | Инструкций VS3 | Выборок PS3 | Арифметических инструкций PS3 |
|---|---:|---:|---:|
| TerrainShader_Graphical | 49 | 20 | 239 |
| TerrainShader_General | 53 | 22 | 236 |
| BeachShader_Graphical | 50 | 20 | 237 |
| BeachShader_General | 51 | 22 | 234 |

По сравнению с предыдущим плавным вариантом число выборок текстур, набор samplers и назначение sampler-регистров сохранены; увеличена только арифметика. Новые художественные материалы и DDS для этой правки не требуются.

Для Intel Iris Xe Graphics, драйвер32.0.101.7088, непосредственно прочитаны D3D9caps: максимальная текстура16384×16384, VS3/PS3,256константVS. Это подтверждает возможности устройства, но не заменяет проверку текущего игрового рендера и производительности.

## Проверки и ограничения

Математическая проверка включает14130двусторонних сравнений в диапазоне карты и за её границами, включая отрицательные координаты; отдельно проверены границы клеток noise и зеркального адресования. При epsilon1e−6 максимальная разница синтетического цвета —1.64e−7, на границах noise —3e−12, на зеркальных границах после clamp —0. Проверены диапазон UV, неотрицательность весов и сумма1.

Непрерывность не означает отсутствия художественных повторов вообще. Читаемость близких типов, остаточная заметность отражённых мотивов, производительность и вид политической карты проверяются в настоящем GUI. CPU-превью должно использовать именно новые индивидуальные UV и noise-веса, а не старую общую зеркальную сетку. Оно остаётся иллюстрацией без colormap, освещения, переходов между типами и сезонных эффектов.

CRLF исходного FX сохранён. Исходник предыдущего рабочего шейдера, точные формулы, логи, ASM и `chaos-validation.json` — в `.work/terrain-variants/`. EXE, игровые текстуры и Git этой стадией не изменялись; корневой FX обновлён по разрешению главного агента.
