# Пересчёт уровней жизни в autogen

Стадия реализации подготовлена в сабмодуле `autogen`, исходная версия — `0a880c6`. Финальная генерация выполняется главным агентом после интеграции исторических типов и параметров местности.

## Правило

`maxLifeRating = max(10, 40 − trunc(attrition × 10))`. При `attrition >= 3` результат сразу ограничивается десятью: это исключает беззнаковое переполнение и преобразование чрезмерно больших значений. Отрицательные и нечисловые значения отклоняются проверкой.

Провинция с `owner` получает ровно этот предел; без владельца — минимум прежнего уровня и предела. Значения `NONE`, `---` и пустая строка считаются отсутствием владельца. Контролёр, колониальный статус и национальные претензии не участвуют.

Базовое состояние обрабатывается первым. Датированные блоки сортируются по числовым году, месяцу и дню; владелец и местность наследуются. Когда новое владение или местность требуют другого уровня жизни, значение вставляется в соответствующий исторический блок. Явные поздние `life_rating` также пересчитываются. Недатированные `party_loyalty` и `state_building` не считаются состояниями истории.

## Запись

`FixProvincesFiles` заменяет значения по смещениям исходных байтов вместо повторной сериализации всей провинции. Сохраняются комментарии, существующая кодировка, переводы строк и остальные поля. Существующее поведение записи `trade_goods` сохранено для других пользователей генератора; эта задача не меняет их значений. Новые датированные `life_rating` добавляются после существующего перевода строки за открывающей скобкой без лишней пустой строки; в однострочных блоках — как скалярное поле в той же строке. Повторные блоки одной даты сопоставляются с последовательными состояниями по порядку вхождений. Регрессии проверяют совпадение исходных байтов после удаления вставленной строки и разный результат двух блоков одинаковой даты.

В обычной игре динамических событий пересчёта нет: изменения применяются к данным исторического старта, пользовательские сейвы не переписываются.

## Проверки

Сборка в собственной копии `.work/terrain-autogen-build/source` с существующим Boost 1.83, MSBuild 17.8.3, MSVC v143:

```powershell
MSBuild.exe .work/terrain-autogen-build/source/autogen.sln /t:run_program /p:Configuration=Release /p:Platform=x64 /p:PlatformToolset=v143 /m
MSBuild.exe .work/terrain-autogen-build/source/autogen.sln /t:unit_tests /p:Configuration=TestRelease /p:Platform=x64 /p:PlatformToolset=v143 /p:PostBuildEventUseInBuild=false /m
```

Release-сборка успешна. Исполняемый файл: `.work/terrain-autogen-build/source/x64/Release/run_program.exe`.

Из рабочего каталога `source/unit_tests` выполнено:

```powershell
../x64/TestRelease/unit_tests.exe --run_test='!DataTests/GoodProvincesTests' --log_level=message
```

Прошли **24 теста**: существующие тесты парсера и данных, интеграционные проверки чтения владельца/исторической колонизации, а также пять новых сценариев. Последние проверяют повышение и снижение уровня у владельца, сохранение низкого значения без владельца, дробное истощение, нижний предел, наследование местности и владельца, хронологический порядок, сохранность байтов и идемпотентность. Дополнительно проверены владельцы `NONE`/`---`, числовой порядок месяцев 2 и 10, повторные даты и запись однострочных блоков.

Оставшийся старый `DataTests/GoodProvincesTests/Test1` не проходит сравнение фиксированной таблицы товаров. Тот же сбой подтверждён отдельной пересборкой с исходным `HEAD:comands/data.cpp`; он не относится к изменениям уровня жизни. Посторонний тест не исправлялся.

`git diff --check` проходит. Игровые истории, сейвы, другой генератор `D:/autogen`, Git/index и тестовая игра на этой стадии не изменялись. Финальная генерация и проверка игры остаются интеграционными проверками всей задачи.
