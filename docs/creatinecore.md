# CreatineCore в этой сборке

Используется CreatineCore 6.43, upstream `7d9f9df9b356096cde475ebd550fbb0102fa1042`, с локальными исправлениями. Русская сборка игры и EXE версии 3.04 сохраняются. Состав установленных DLL и хеши записаны в `z_CreatineCore/install-manifest.json`.

Включены расширенные условия и эффекты событий/решений, исправления отложенного FROM, флагов провинций, модификаторов POP, технологий, правил приоритета фабрик, пополнения войск, союзных транспортов, размещения поддержки во второй линии и музыка. Действующий профиль — `z_CreatineCore/creatinecore_settings.ini`; `tools/creatinecore-profile/creatinecore_settings.ini` служит шаблоном. Установщик сохраняет существующие настройки пользователя.

Перенаправление урона во вторую линию отложено по согласованию с пользователем: upstream принудительно отключает его из-за неверного адреса функции. Одного выставления флага недостаточно. Многопоточные оптимизации и квантование POP не включены.

Цены экспоненциальные; расширение потолка включено (`TRADE_MAX_PRICE_20X_MULTIPLIER=1`). Фабричный резерв 3000 на уровень увеличивает запас денег и откладывает выплаты владельцам, но не является универсальной защитой от переполнений. В действующем пользовательском профиле содержание зданий и цвета вассалов отключены (`BUILDING_GOODS_CONSUMPTION=0`, `ENABLE_VASSAL_COLORS=0`); эти настройки сохраняются. Глобальная прибавка доходов POP равна нулю; возможность скриптового `pop_income_modifier` доступна.

## Национальные провинции великих держав

Дополнительный модуль GPC включён: `z_CreatineCore/great_power_culture_cores.ini`,
`ENABLE_GREAT_POWER_CULTURE_CORES=1`, `GREAT_POWER_CULTURE_CORES_MTTH_MONTHS=60`.
Один общий случайный процесс проверяет все текущие великие державы. При
срабатывании подходящие получатели получают корки в одном проходе, затем каждую
страну с положительным результатом уведомляет русское событие 3997200.

Требуется изученная `nationalism_n_imperialism`, если технология есть в базе.
Учитывается только основная культура державы. Она должна входить в множество
крупнейших культур провинции по сумме всех POP; при ничьей учитываются все лидеры.
Провинция должна принадлежать другой стране, существующие корки не добавляются
повторно. Выданные корки не отзываются этой механикой. При подключении к старому
сейву начинается обычное случайное ожидание, немедленной выдачи при загрузке нет.

В [эксперименте 1836](research/gpc-1836-validation.md) без технологии результат
был нулевым. После её точечной тестовой выдачи Пруссия получила 35 новых корок,
Австрия — 21. В обычной партии эта технология доступна для исследования с 1850 года.
Открытые окна уведомлений не восстанавливаются проверенным native save/UI-путём;
сами корки и расписание сохраняются. Подробности — в
[руководстве модуля](../tools/creatinecore/gpc/README.md) и
[отчёте о сохранении уведомлений](research/gpc-notification-save-contracts.md).

## Сборка и установка

```powershell
python tools/creatinecore/build.py
python tools/creatinecore/test_config_alias.py
python tools/creatinecore/validate_native_sites.py
python tools/creatinecore-profile/prepare.py
python tools/creatinecore/install.py --destination D:/v2game
```

Требуются установленный MSVC 2026 Win32, Git и Python 3.12. Для первой загрузки исходников нужен доступ к GitHub. В среде Codex MSBuild может требовать разрешённого запуска вне песочницы. Установщик проверяет хеши EXE и DLL, сохраняет прежние файлы в `.work/install-backups` и не устанавливает отладочный канал в обычную игру.

Исходный план и пользовательские дополнения находятся в `docs/plans`. Полный откат сборки включает согласованные коммиты игровых данных и DLL: удаление одного загрузчика не отменяет изменения defines, переводов или добавленный расширенный синтаксис скриптов.

## Тестирование из командной строки

```powershell
tools/vic2test/build.cmd
python tools/vic2test/cli.py prepare --destination .work/test-run --save "D:/Documents/Paradox Interactive/Victoria II/save games/isolation_baseline.v2"
```

В тестовую копию устанавливаются ядро, профиль и `tools/vic2test/.build/vic2_test_bridge.dll` в `game/z_CreatineCore/dll_Submods`. Обычная игра не получает этот тестовый плагин. Затем:

```powershell
python tools/creatinecore/install.py --destination .work/test-run/game
Copy-Item tools/vic2test/.build/vic2_test_bridge.dll .work/test-run/game/z_CreatineCore/dll_Submods/
Copy-Item tools/vic2test/fixtures/* .work/test-run/game/mod/ -Recurse -Force
```

Для сценариев из `fixtures` добавлять к `start` параметр `--mod vic2test.mod`.

```powershell
python tools/vic2test/cli.py start --environment .work/test-run --save isolation_baseline.v2 --hidden
python tools/vic2test/cli.py status --environment .work/test-run
python tools/vic2test/cli.py decision check --environment .work/test-run --tag HAW --id decision_name
python tools/vic2test/cli.py event --environment .work/test-run --tag HAW --id 123 --option 0
python tools/vic2test/cli.py advance --environment .work/test-run --days 30
python tools/vic2test/cli.py save --environment .work/test-run --name new_checkpoint
python tools/vic2test/cli.py stop --environment .work/test-run
```

Команды загрузки, выбора опции, решений, сохранения и хода времени исполняются внутри настоящего движка без синтетических кликов и клавиатуры. Опции нумеруются с нуля. Выполнение решения и выбранной опции поддерживается для страны игрока; `event --province <ID> --id <event> --option <N>` выполняет провинциальное событие в принадлежащей игроку провинции. Провинциальный путь использует настоящий `CEvent::run`: у консольного обработчика обнаружена неверная область выполнения. Произвольные снимки всех полей POP не реализованы; условия флагов и модификаторов проверяются нативными условиями тестовых решений. В исправной SP-сессии другую кампанию можно загрузить через `return-menu` и `load --save <имя>`; после загрузки завершить первый день перед GPC-диагностикой. Для изменённых скриптов, после неопределённого результата или нативного исключения запускать новый процесс.

Настоящий host/client, выбор стран, начало партии, пауза, скорость и сохранение
управляются без мыши и клавиатуры через `tools/vic2test/mp_driver.py`.
[Руководство CLI](../tools/vic2test/README.md) описывает подготовку двух сред,
сравнение файлов, подтверждения обоих участников и перехост. Обычные локальные
SP-мутации в MP запрещены; принудительный GPC-проход также отклоняется.

Пример воспроизводимого сценария и русский тестовый мод находятся в `tools/vic2test/fixtures`. Сценарий проверяет однократный immediate, выбранную опцию, точные изменения казны и запрет повторного решения. Статическая команда `check` проверяет структуру и дубли ID; она не вычисляет условия движка.

Обычный `advance` останавливается при требующем выбора событии. Для автономного длительного регрессионного прогона можно явно добавить `--auto-events`: движок выбирает первые опции фоновых событий только на время этого прогона и возвращает их количество. Такой прогон проверяет работоспособность, а не повторяет решения человека в исходной кампании. Явно вызванное событие, ожидающее выбора теста, этим режимом не перезаписывается.

## GUI

Пользователь разрешил Python для снимков, мыши и клавиатуры. `tools/gui_check.py --pid <PID> --environment .work/test-run --output .work/screen.png` проверяет полный путь тестового процесса. `--show` показывает скрытое окно; `--click X Y` использует физические координаты клиентской области, `--key` — код клавиши Windows. При отсутствии фокуса ввод отменяется. Скрипт учитывает DPI; экран 3200×2000 при масштабе 200% не трактуется как 1600×1000.

Исходные пользовательские сейвы не изменяются. Тестовые сейвы, логи, снимки и сборки остаются в `.work` вне Git. Результаты фактически выполненных проверок записываются в `docs/research/validation.json`.
